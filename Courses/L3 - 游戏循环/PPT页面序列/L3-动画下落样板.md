## 页面 2/7 · 伪代码骨架页 ⭐（先看思想，再看代码）

**标题：** 先看下落：一列一列，压实 + 补货

**页面内容（伪代码 + 图示）：**

```
fall_and_refill（下落 + 补新）
│
├─ 1. 开个"记账本" movers：记录每颗要动的宝石 → 落到哪 → 花多久
│
├─ 2. 逐列处理（8 列）：
│     ① 现有宝石下沉：自下而上扫
│        下面有洞 → 数据搬下去，记一笔"要下落 X 格"
│     ② 顶部补新：空位生成新宝石
│        起点放在屏幕外上方（行 -1, -2…）→ 记一笔"要下落 Y 格"
│
└─ 3. 一次性播放：一个并行 Tween 同时播所有下落动画
      （await 一次，全部播完再返回）
```

**配图（一列宝石下落演示）：**

```
[红] ← 新补的（从屏幕外 -1 行落入）
[空]                                 [蓝] ← 新补的
[蓝] ──压实──▶ [红]                  [红] ← 上面掉下来的
[红]             [蓝]                  [绿] ← 上面掉下来的
[绿]             [红]                  [蓝] ← 上面掉下来的
[空]             [绿]    补新后：
[蓝]             [蓝]    顶部生成新宝石，起点在屏幕外
```

**人话：** 下落 = **先记账、后播放**。第一步把所有"要动的宝石"记下来（谁、去哪、多久），第二步一次性播动画——这就是数据与表现分离的进阶版（第 2 课交换动画也是这思路）。

**代码地图标签：** 📍 伪代码 ↔ `board.gd` → ⑪ fall_and_refill

**讲师口播：**
「先看思想，再看代码。整个函数分三步：**开记账本 → 逐列压实补货 → 统一播动画**。注意细节：①扫列要**自下而上**——从底下往上压实，像往杯子里倒沙子；②新宝石的起点在**屏幕外上方**（行 -1、-2），所以视觉上是"排队落下来"；③所有移动先记账，最后**一个并行 Tween 一起播**——不是一颗一颗播。记住这三步，下一页对号入座。」

## 页面 3/7 · 全貌页

**标题：** 动画模板 T3 + fall_and_refill —— 完整代码

**页面内容①（T3 动画模板 —— 一颗宝石怎么动）：**

```gdscript
## 动画③：下落（移动到目标位置，时长由下落格数决定——格数多花的时间长）
func animate_fall_to(target: Vector2, duration: float) -> void:
	var tween := create_tween()
	tween.tween_property(self, "position", target, duration)
	await tween.finished            # T3 模板：等动画播完才继续
```

**页面内容②（fall_and_refill 完整代码，供对照）：**

```gdscript
func fall_and_refill() -> void:
	var movers: Array = []                              # 记账本
	for col in range(GRID_SIZE):
		var write_row: int = GRID_SIZE - 1              # 从最底行开始找"落点"
		for row in range(GRID_SIZE - 1, -1, -1):        # 自下而上扫
			var gem: Gem = grid[col][row] as Gem
			if gem == null:
				continue
			if write_row != row:                        # 下面有空洞 → 需要下落
				grid[col][row] = null
				grid[col][write_row] = gem
				var from_row: int = gem.grid_pos.y
				gem.grid_pos = Vector2i(col, write_row)
				var cells: int = write_row - from_row
				var duration: float = maxf(FALL_PER_CELL, float(cells) * FALL_PER_CELL)
				movers.append({"gem": gem, "target": grid_to_world(Vector2i(col, write_row)), "duration": duration})
			write_row -= 1
		var spawn_index := 0
		while write_row >= 0:                           # 顶部补新
			var target_pos := Vector2i(col, write_row)
			var start_pos := Vector2i(col, -1 - spawn_index)   # 起点在屏幕外
			var gem2: Gem = _spawn_gem(random_gem_type(), target_pos)
			gem2.position = grid_to_world(start_pos)
			grid[col][write_row] = gem2
			var cells2: int = write_row - start_pos.y
			var duration2: float = maxf(FALL_PER_CELL, float(cells2) * FALL_PER_CELL)
			movers.append({"gem": gem2, "target": grid_to_world(target_pos), "duration": duration2})
			spawn_index += 1
			write_row -= 1
	if movers.is_empty():
		return
	var tween: Tween = create_tween()                  # 统一播放下落
	tween.set_parallel(true)
	for item in movers:
		tween.tween_property(item["gem"] as Gem, "position", item["target"] as Vector2, item["duration"] as float)
	await tween.finished
```

**页面内容③（对照提示）：** 伪代码三步 = 代码三段：记账本（movers）→ 双层处理（压实 + 补新）→ 并行 Tween 统一播。**长得一样，只是多了细节。**

**代码地图标签：** 📍 `gem.gd` → ④ 动画三件套 + `board.gd` → ⑪ 下落填充

**讲师口播：**
「看全貌——上面是 T3 动画模板（一颗宝石怎么动，就 4 行），下面是 fall_and_refill 全貌。是不是跟伪代码对得上？记账本、逐列处理、统一播放。别被 40 行吓到——**真正要懂的就两个点**：串行为什么必须 await（下一页），下落为什么自下而上 + 按格数算时长（再下一页）。」

## 页面 4/7 · 分段精讲① —— T3 串行模板（本页核心 ⭐）

**标题：** 为什么动画必须"等"？（await = 动画的刹车）

**页面内容（对比演示 + 代码）：**

```
❌ 不 await（并发）：
   消除动画播到一半 → 下落已经开始 → 两颗宝石位置交叉 → 乱飞穿帮

✅ await 串行：
   消除动画播完 → 才播下落 → 再播下一个 → 顺序清清楚楚
```

```gdscript
## 动画②：消除（缩小 + 淡出，两个效果同时进行）
func animate_clear() -> void:
	var tween := create_tween()
	tween.set_parallel(true)                    # 并行模式：缩小和淡出一起播
	tween.tween_property(self, "scale", Vector2(0.2, 0.2), 0.2)
	tween.tween_property(self, "modulate:a", 0.0, 0.2)
	await tween.finished                        # ← T3 模板：等这组播完

## 调用方（clear_matches 里）：只 await 第一颗
await first.animate_clear()                     # 等第一颗播完 = 所有都播完
```

**人话（T3 模板，可背）：**
- **`await tween.finished` = 动画的刹车**：告诉游戏"这段动画播完之前，别往下走"
- **并行 vs 串行**：一个动画**内部**可以并行（缩小+淡出一起）；动画**之间**必须串行（消除完才下落）
- **多颗同时播的技巧**：clear_matches 里 5 颗宝石同时消除——全部开播，但**只 await 第一颗**（所有动画时长一样，第一颗播完 = 全部播完）
- 为什么 await 没写会乱？宝石还在半空中，下一段动画又改它的位置——**同一颗宝石同时被两个 Tween 控制，必然穿帮**

**板书：** 画时间轴：`消除动画 ──await──▶ 下落动画 ──await──▶ 结束`

**代码地图标签：** 📍 `gem.gd` → ④ 动画三件套 · T3 模板

**讲师口播：**
「这是今天第一个重点——**T3 模板：`await tween.finished`**。把它想成刹车：动画播完之前，代码停在这行不往下走。为什么必须刹？想想：消除动画播到一半，下落动画又去改同一颗宝石的位置——**一颗宝石同时被两个动画控制，不穿帮才怪**。注意区分：一个动画内部可以并行（缩小和淡出一起），但动画之间必须串行。还有个技巧：多颗宝石同时消除，全开播但只等第一颗——因为时长一样，第一颗播完就等于全部播完。这个技巧 clear_matches 里用了，省时间。」

## 页面 5/7 · 分段精讲② —— 下落算法核心：自下而上压实

**标题：** 下落的核心：自下而上 + 按格数算时长

**页面内容（代码高亮 + 图示）：**

```gdscript
		var write_row: int = GRID_SIZE - 1              # 落点：从最底行开始
		for row in range(GRID_SIZE - 1, -1, -1):        # 自下而上扫
			var gem: Gem = grid[col][row] as Gem
			if gem == null:
				continue
			if write_row != row:                        # 下面有洞 → 搬下去
				grid[col][row] = null
				grid[col][write_row] = gem
				gem.grid_pos = Vector2i(col, write_row)
				...
				movers.append({"gem": gem, "target": ..., "duration": ...})
			write_row -= 1                              # 落点上移一格
```

**配图（自下而上演示）：**

```
第 5 行: [空]         第 5 行: [空]
第 4 行: [蓝]  ← 扫描  第 4 行: [空]   ← 蓝搬到 write_row=5，落点变 4
第 3 行: [空]         第 3 行: [空]
第 2 行: [红]         第 2 行: [空]   ← 红搬到 write_row=4，落点变 3
第 1 行: [绿]         第 1 行: [绿]   ← 绿已经在 write_row=1，不动
第 0 行: [空]         第 0 行: [空]
```

**人话（三个要点）：**
1. **为什么自下而上**：`write_row` 从底往上走，保证每个空洞只被填一次——从上往下扫会把宝石"卡"在半路
2. **数据先行**：先搬 grid 数据 + 改 grid_pos，动画后播（第 2 课老套路：数据与表现分离）
3. **时长按格数**：`duration = 格数 × FALL_PER_CELL`（0.08 秒/格）——落 3 格 0.24s、落 1 格 0.08s，**近似恒速**，视觉自然。`maxf` 保证最少也有一帧时长

**代码地图标签：** 📍 `board.gd` → ⑪ 下落填充 · ① 现有宝石下沉

**讲师口播：**
「看下落的核心——`write_row` 这个"落点指针"从最底行往上走，扫到的宝石如果下面有洞就搬下去。**为什么必须自下而上？** 想想从上往下扫：上面的宝石搬下去填了洞，但它的"落点"计算就乱了，宝石会卡在半路。自下而上 = 每个空洞只被填一次，稳。还有个细节：**数据先搬、动画后播**——grid 表和 grid_pos 先更新，动画只是"表演"。时长按格数算：落 3 格 0.24 秒，落 1 格 0.08 秒——不管多远，速度都一样，看起来才像真的重力。」

## 页面 6/7 · 分段精讲③ —— 顶部补新 + 统一播放（movers 记账）

**标题：** 补货 + 一起动：movers 记账本最后兑现

**页面内容（代码高亮）：**

```gdscript
		var spawn_index := 0
		while write_row >= 0:                           # 还有空位 → 补新
			var target_pos := Vector2i(col, write_row)
			var start_pos := Vector2i(col, -1 - spawn_index)   # 起点：屏幕外 -1, -2…
			var gem2: Gem = _spawn_gem(random_gem_type(), target_pos)
			gem2.position = grid_to_world(start_pos)   # 先放到屏幕外上方
			grid[col][write_row] = gem2
			...
			movers.append({...})
			spawn_index += 1
			write_row -= 1
	...
	var tween: Tween = create_tween()                  # 记账完毕，统一兑现
	tween.set_parallel(true)
	for item in movers:
		tween.tween_property(item["gem"] as Gem, "position", item["target"] as Vector2, item["duration"] as float)
	await tween.finished
```

**人话（两个技巧）：**
1. **新宝石从屏幕外排队落入**：起点 `行 -1`、`-2`……越靠上的空位起点越高——视觉上是"补货机从上往下补"，而不是凭空出现
2. **movers 记账本模式**：所有移动先记进数组（谁、去哪、多久），最后**一个并行 Tween 一起播**——而不是边扫边播。好处：所有宝石**同时开始下落**，速度一致、观感统一；代码也只 await 一次
3. `_spawn_gem` 是 L1 学过的（照图纸 instantiate + setup）——新宝石也是图纸造出来的，只是先放屏幕外

**代码地图标签：** 📍 `board.gd` → ⑪ 下落填充 · ② 顶部补新 + ③ 统一播放

**讲师口播：**
「最后看补货和播放。**新宝石从哪来？** 屏幕外——起点在行 -1、-2，越靠上的空位起点越高，所以视觉上是排队落下来的，不是凭空变出来。**为什么先记账后播放？** 想想：如果边扫边播，第 1 颗先开始落，第 5 颗后开始——速度不一样，画面乱。记账本模式让**所有宝石同时开始、同时结束**，观感统一，代码也只 await 一次。这个模式以后写动画会反复用——**先记账、后兑现**。」
