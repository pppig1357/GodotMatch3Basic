## S1 · 函数概念：输入 → 处理 → 输出（实操前置 10min）

**标题：** 函数是什么？榨汁机

**页面内容（概念图）：**

```
        ┌─────────────┐
  水果 ──▶  榨汁机    ──▶ 果汁
 （输入）  （处理）    （输出）

函数也一样：
  groups（匹配组数组）──▶ 处理：遍历 + 数个数 + 套公式 ──▶ 总分（int）
```

**人话（函数概念）：**
- **函数 = 输入 → 处理 → 输出**：把一段逻辑装进一个"盒子"，给它输入，它给你输出
- **为什么需要函数**：①复用——消除计分、以后别处可能也要算分，写一次到处用 ②分工——别人只需要知道"调用它就能算分"，不用管里面怎么算（黑盒思想，跟 L2 的 board 一个套路）
- 你已经见过很多函数了：`find_matches()`、`grid_to_world()`、`get_gem_at()`——今天轮到你**自己造一个**

**讲师口播：**
- 函数 = **输入 → 处理 → 输出**，就像榨汁机：水果进去（输入），果汁出来（输出）
- 你们其实已经用了一堆函数——`find_matches()` 输入棋盘、输出匹配组；今天要自己造一个：`_calc_score` 输入匹配组、输出总分
- 为什么需要函数？**复用**（写一次到处用）+ **分工**（调用的人不用管内部）——这就是 L2 黑盒思想的正面版本

**验证点：** 能说出函数三要素（输入/处理/输出）。

## S2 · 函数语法：func 名字(参数) -> 返回类型

**标题：** 函数的"长相"：签名长这样

**页面内容（语法拆解）：**

```
func 函数名(参数: 类型) -> 返回类型:
	函数体（处理逻辑）
	return 结果

实战（我们的实操题）：
func _calc_score(groups: Array) -> int:
	# 函数体：你来写
	pass        # pass = 空占位（什么都不做）
```

**人话（语法四要素）：**
1. `func` = 声明"这是个函数"（function 缩写）
2. `_calc_score` = 函数名（下划线开头 = 私有，本文件内部用）
3. `(groups: Array)` = **参数**：调用方传进来的输入，类型 Array（数组）
4. `-> int` = **返回类型**：这个函数最后给回一个整数（总分）——**写了 -> int 就必须 return 整数**，否则报错

**讲师口播：**
- 函数签名四要素：**func 关键字、名字、参数（带类型）、返回类型**（`-> int`）
- 注意最后那个 `-> int`：声明了"我返回一个整数"，函数体里**就必须有 return 整数**——这是 Godot 的规矩，少了会报错（待会儿实操最容易踩的坑）
- `pass` 是占位：函数体先空着，不会报错——我们的实操模板就是给你一个带签名的空壳

**验证点：** 能指出签名四要素。

**页面内容①（先看它怎么被调用 —— 别急着写，先认识它的"雇主"）：**

→ clear_matches 需要 _calc_score 输出一个【总分 int】，

**讲师口播：**
- **先别急着写**——先看你的函数将来怎么被用（黑盒视角）：clear_matches 里 `var base: int = _calc_score(groups)`，它需要你返回一个**总分 int**，然后 `base * chain` 加进分数
- 所以你要写的函数就是：**吃进匹配组数组（groups），吐出总分（int）**——规则 3 个 30 分、多 1 个 +10

- 例子算一遍：一组 3 连（30）+ 一组 4 连（40）= 70 分
- 模板在实操文件里（`Courses/实操模板/L3-calc-score.md`）——**函数签名、注释我都写好了，你们填函数体**

## S4 · 讲师示范：完整写一遍（逐行讲）

**标题：** 讲师示范：一行一行来

**代码块（参考答案，现场逐步写）→ 📌 归属：board.gd ⑩ 消除计分区：**

```gdscript
func _calc_score(groups: Array) -> int:
	var total := 0                  # ① 开"总分"账本，初始 0
	for group in groups:            # ② 遍历每一组
		var n: int = group.size()   # ③ 数一数这组几颗
		if n >= 3:                  # ④ 够 3 个才算分
			total += 30 + (n - 3) * 10   # ⑤ 套公式累加
	return total                    # ⑥ 交回总分
```

**逐行口播：**
- ① `var total := 0`：先开个"总分"账本（跟 movers 记账本一个思路）
- ② `for group in groups:`：一组一组来——遍历，L1 生成棋盘学过
- ③ `var n := group.size()`：这组有几颗宝石？`.size()` 数数组长度
- ④ `if n >= 3:`：**≥3 才算分**（不是 >3——3 个的组也要算！）
- ⑤ `total += 30 + (n - 3) * 10`：公式——3 个 = 30，4 个 = 30+10=40
- ⑥ `return total`：交回总分（签名写了 `-> int`，必须有 return）

**验证点：** 学员抄完能跑（F5 无报错）。

## S5 · 积木箱：这次实操会用到的一切（卡住看这里）

**标题：** 积木全在这了，照着拼就行

**页面内容（积木箱速查）：**

```
积木箱（都是前面课学过的，标记来源）：
  声明变量  var total := 0            ← L1（开"总分"账本）
  遍历循环  for group in groups:     ← L1（一组一组处理）
  数组长度  group.size()             ← L2（这组有几颗）
  条件判断  if n >= 3:               ← L2（够 3 个才算分）
  累加赋值  total += 30 + (n - 3) * 10  ← 套公式加分
  返回      return total             ← 交回总分

拼装顺序：开账本 → 遍历 → 数数 → 判断 → 累加 → 返回

防手抖（巡视常见错误）：
  ❌ 忘写 return total        → 报错（-> int 必须返回）
  ❌ group.size() 少括号      → 报错（size 是函数要带 ()）
  ❌ if n > 3                 → 3 连的组被跳过（应该 >= 3）
  ✅ 空数组传入              → 循环不执行，返回 0（正常）
```

**讲师口播：**
- **积木箱思路**：这次实操不用你们创造新东西——用的变量/循环/判断/返回值全在前面课程学过，我把积木全列出来了，**你们的工作就是照着拼装顺序把它们拼成一个函数**（开账本 → 遍历 → 数数 → 判断 → 累加 → 返回）
- 每块积木标注了哪课学的：`var`（L1）、`for`（L1 生成棋盘）、`.size()`（L2）、`if`（L2 判定）、`+=`、`return`——都是见过的
- 四个防手抖点：忘 return 会报错；size 少括号会报错；`n > 3` 会让 3 连漏算（必须 `>= 3`）；空数组传进来返回 0 是正常行为

## K1a · clear_matches（上）：计分 + ①清数据

**标题：** clear_matches（上）：先计分，再把数据清掉

**📌 动手前（溯源 L1/L2 声明区）→ 📌 归属：board.gd 顶部（信号 + 变量区）：** 在 board.gd 顶部常量/变量区**新增三行声明**：

```gdscript
signal score_changed(score: int)   # 分数变化 → HUD 刷新（L4 讲透信号）
signal match_cleared               # 开始消除 → Main 播消除音效
var score: int = 0                 # 当前分数
```

> ⚠️ 又是"用到即声明"：计分是 L3 才有的功能，`score` 变量和两个信号在 L1/L2 都没声明过——写 clear_matches 前先补上（不声明 F5 报 `Identifier not declared`，跟 FALL_PER_CELL 一个坑）
> 🔮 信号现在只用"发出去有人响应"（黑盒），L4 信号流拆开讲

**代码块 → 📌 归属：board.gd → ⑩ 消除计分（clear_matches 上半）：**

```gdscript
func clear_matches(matches: Array, chain: int) -> void:
	match_cleared.emit()                    # 发信号 → Main 播消除音效
	var groups: Array = find_match_groups() # 按"组"计分（3个=30分）
	var base: int = _calc_score(groups)     # ← 实操函数在这被调用
	var gained: int = base * chain          # 连锁倍率 ×2 ×3…
	score += gained
	score_changed.emit(score)               # 发信号 → HUD 刷新分数

	# ① 清数据（grid 置 null）
	for gem in matches:
		if gem == null: continue
		var g: Gem = gem as Gem
		grid[g.grid_pos.x][g.grid_pos.y] = null
```

**人话：**
1. **计分在消除之前**：先算分（`_calc_score` + 连锁倍率）→ 发信号让 HUD 刷新 → 才开始"动手消"
2. **①清数据**：把要消的宝石在 grid 表里置 null——数据先清，动画后播（L2 老套路：数据与表现分离）
3. **按组计分**：`find_match_groups` 重新分组——L 形共用一颗的组分开算（L2 判定层伏笔）

**讲师口播：**
- 上半场两件事：**计分 + 清数据**。注意顺序——分数先算、信号先发，然后才动棋盘数据
- **动手前先补声明**：`score_changed` / `match_cleared` 两个信号 + `score` 变量，加在 board.gd 顶部（L1/L2 没声明过——计分是 L3 才有的，用到就声明，跟 FALL_PER_CELL 一个坑）；信号现在是黑盒，`emit` 发出去有人响应（谁响应？L4 信号流拆开讲）
- `_calc_score(groups)` 就是你们刚实操写完的函数——基础分算完 × 连锁倍率
- ①清数据：grid 里置 null，**画面还没动**——数据先动，动画只是表演（和 L2 交换、L3 下落一个套路）

## K1b · clear_matches（下）：只 await 第一颗 + 删节点 ⭐

**标题：** clear_matches（下）：5 颗同时消，只等第一颗

**代码块 → 📌 归属：board.gd → ⑩ 消除计分（clear_matches 下半）：**

```gdscript
	# ② 并行播消除动画——只 await 第一颗
	var first: Gem = null
	for gem in matches:
		var g2: Gem = gem as Gem
		if g2 == null: continue
		if first == null: first = g2
		else: g2.animate_clear()
	if first != null:
		await first.animate_clear()
	# ③ 动画后删节点
	for gem in matches:
		if gem != null and is_instance_valid(gem):
			(gem as Gem).queue_free()
```

**人话（技巧，可背）：**
1. **为什么只 await 第一颗**：所有宝石动画时长一样（都 0.2 秒）→ 一起开播 → **第一颗播完 = 全部播完**——等一次代表全部
2. **② 播动画**：3~5 颗宝石同时缩小+淡出（调 `gem.animate_clear`，A 系列讲过）——播放是并行的，等待是串行的
3. **③ 删节点**：动画播完才 `queue_free`（安全延迟删除）——先看消失动画，再从场景树移除

**讲师口播：**
- 这是"**并行播放、串行等待**"的完美例子：播放一起动（每颗自己的 Tween），等待只一次（第一颗播完 = 全部播完）
- 前提是**时长一样**——记住这个前提，动画时长不同就不能这么等
- `queue_free` 是延迟删除：节点在帧末才真正移除——动画播完再删，不会闪断

## K2 · 计分流程：基础分 × 连锁倍率

**标题：** 分数怎么涨？基础分 × 连锁倍率

**页面内容（流程 + 例子）：**

```
计分 = 基础分（_calc_score）× 连锁倍率（chain）

例 1：第一次消除，一组 3 连
  基础分 = 30（3 个 = 30 分）

```

**人话：**
- **基础分**：只看这一组几个宝石（3 个 30、4 个 40）——规则由 `_calc_score` 定（就是你刚写的）
- **连锁倍率**：第 n 次消除 ×n——鼓励连锁，这是三消的爽感引擎
- 两个信号（match_cleared / score_changed）：发出去 Main 和 HUD 会自动响应——L4 信号流细讲，现在只用

## C1 · 总装：T2 伪代码先行（resolve_board，模板 T2 ⭐）

**标题：** 先看循环：消除 → 下落 → 再检查（连锁的秘密）

**页面内容（伪代码 + 图示）：**

```
结算开始
│
└─ while true（无限循环）:
     ├─ 检查：还有匹配吗？
     │    ├─ 没有 → break（结算结束）
     │    └─ 有 → 继续：
     │         ├─ 消除 + 计分（第 1 次 ×1，第 2 次 ×2，第 3 次 ×3…）
     │         ├─ 下落 + 顶部补新
     │         └─ 回循环开头再检查 ← 连锁！
```

**人话：** 连锁 = **循环重复**。一次消除可能引发新的匹配（下落重新排列宝石）——循环就是"只要还有得消就继续消"。chain 每次 +1：**连锁越深，分数越爆炸**——这就是三消上头的核心机制。

**讲师口播：**
- 看这个循环——`while true` 无限循环，每次三件事：**检查 → 有就消除计分 → 下落补新**，然后回开头再检查
- 为什么还要检查？**下落之后宝石重新排列，可能又凑出新三消**——这就是连锁
- **T2 模板（可背）**：`while 有匹配: 消除 → 下落`

**验证点：** 无，先看思想。

## C2 · 总装：resolve_board 全貌（10 行代码）

**标题：** resolve_board —— 循环的代码长这样（10 行）

**代码块（复制粘贴处）→ 📌 归属：board.gd ⑨ 结算循环：**

```gdscript
func resolve_board() -> void:
	var chain := 1
	while true:
		var matches: Array = find_matches()
		if matches.is_empty():
			break                        # 没有匹配了，结算结束
		await clear_matches(matches, chain)   # 消除 + 计分
		await fall_and_refill()               # 下落 + 顶部补新
		chain += 1                            # 连锁次数 +1
```

**对照提示：** 跟伪代码一模一样——检查（find_matches）→ 消除（clear_matches）→ 下落（fall_and_refill）→ 循环。**10 行，本课最短但最重要的函数。**

**讲师口播：**
- 十行代码，跟伪代码一模一样。`await` 还记得吗？A2 刚讲——**等动画播完再继续**（T3 模板现场应用）：消除播完才下落，下落播完才回循环开头，**顺序不能乱，这就是串行**
- 两个细节：`find_matches` 是 L2 判定层写的——**黑盒复用**；`break` 是唯一出口
- `chain` 从 1 开始：第 1 次 ×1、第 2 次 ×2——它传给 clear_matches 做连锁倍率（K2 已细讲）

**验证点：** 能在 board.gd 里找到这个函数。
