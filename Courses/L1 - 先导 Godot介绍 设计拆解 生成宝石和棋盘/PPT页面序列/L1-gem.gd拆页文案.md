## 页面 A · 继承与身份

**标题：** 继承与身份：extends 和 class_name

**代码块（复制粘贴处）：**

```gdscript
extends Node2D
class_name Gem
```

**讲师讲什么：**
- `extends Node2D`：这个脚本「继承」了 Node2D 的一切——能当节点挂到场景树里，能用 position、scale 这些属性。**脚本 = 给节点写「附加规则」**
- `class_name Gem`：给这个脚本起一个**全局名字**。别的脚本（board.gd）才能写 `var gem: Gem`——「声明一个 Gem 类型的变量」。没有这行，board.gd 只能写 `var gem: Node2D`，拿不到我们自定义的 `type`、`setup()` 这些东西

**小技巧框（官方风格）：** 为什么要声明类型？——提前告诉 Godot「这颗宝石有 type / grid_pos / setup()」，写代码时就有**自动补全**，写错属性名会**立刻报错**，而不是运行时才炸。

**验证点：** 无，继续往下写。

## 页面 B · 给颜色起名字：enum

**标题：** 给颜色起名字：枚举 enum

**代码块（复制粘贴处）：**

```gdscript
enum GemType { RED, BLUE, GREEN, YELLOW, PURPLE, ORANGE }
```

**讲师讲什么：**
- `enum` = 一组**有名字的整数常量**。写完这行，RED 就是 0、BLUE 是 1、……ORANGE 是 5
- 好处：写 `GemType.RED` 比写 `0` 好懂 100 倍。代码里全是 0~5 的数字，谁也记不住 3 是黄色——但 `GemType.YELLOW` 一眼就懂
- ⚠️ **这个顺序很重要**：后面挂贴图、换贴图全靠这个编号。**顺序乱了，颜色就错了**——今天先记住这句话，Page G 会解释为什么

**备注框：** 枚举的顺序 = 编号的顺序。RED 排第 0 位所以是 0——这不是随便排的。

**验证点：** 无，继续。

## 页面 C · @export：检查器里能填的数组

**标题：** @export：检查器里能填的「槽位」

**代码块（复制粘贴处）：**

```gdscript
@export var gem_textures: Array[Texture2D] = []
```

**讲师讲什么：**
- 拆开读：
  - `@export` = 这个变量会显示在**检查器面板**里，可以直接拖资源进去填
  - `Array[Texture2D]` = 一个「装贴图的数组」
  - `= []` = 一开始是**空数组**
- 现在它是空的——稍后我们会回到 Gem 节点，在检查器里往这个数组拖 6 张宝石贴图
- 这是 Godot 最常用的工作流：**代码声明槽位，场景负责填图**。以后想换贴图，去检查器改就行，不用动代码

**小技巧框（官方风格）：** 为什么叫「导出」？——export = 把变量「导出」到检查器，让不懂代码的人（策划/美术）也能改。这就是游戏引擎「数据与表现分离」的第一次接触。

**验证点：** 无，继续。

## 页面 D · 这颗宝石是什么？在哪？

**标题：** 记录两颗信息：type 和 grid_pos

**代码块（复制粘贴处）：**

```gdscript
var type: int = GemType.RED
var grid_pos: Vector2i = Vector2i.ZERO
```

**讲师讲什么：**
- `type`：这颗宝石**当前的颜色编号**（默认红色）。以后消除判定，就是比较两颗宝石的 type 相不相同
- `grid_pos`：这颗宝石在棋盘上的坐标 **(col, row)**——第几列、第几行。`Vector2i` = 整数坐标（结尾的 i = integer 整数）
- 注意：这俩是**数据**，不是表现。贴图长什么样归 Sprite 管；但「我是谁（颜色）、我在哪（坐标）」由这两个变量说了算

**备注框：** `grid_pos` 存的是**网格坐标**不是像素坐标——棋盘是 8×8 的格子，格子和像素是两套坐标系（下一部分 board.gd 会教换算）。

**验证点：** 无，继续。

## 页面 E · @onready：等进树了再找孩子

**标题：** @onready 和 $：拿到子节点

**代码块（复制粘贴处）：**

```gdscript
@onready var _sprite: Sprite2D = $Sprite
# @onready var _select_mask: ColorRect = $SelectMask   # ← 这行先注释掉（第 2 课才用）
```

**讲师讲什么：**
- 宝石长什么样，由子节点 `Sprite` 决定。脚本要操作它，得先「拿到」它——`$Sprite` 就是拿：`$` 是 `get_node()` 的简写，`$Sprite` = 拿名为 Sprite 的子节点
- 为什么要 `@onready`？——脚本刚加载时子节点可能还没准备好。`@onready` = 「等节点进入场景树之后，再取子节点」，保证拿得到
- 第二行 `_select_mask`（选中遮罩）**这节课用不上**，先注释掉，免得未使用变量警告刷屏——第 2 课加选中功能时再把它加回来

**小技巧框（官方原话借用）：** `$` 是 `get_node()` 的简写。⚠️ 节点名**区分大小写**——`$sprite` 和 `$Sprite` 是两回事。拼错名字会得到 null，运行时报错「null instance」（第 2 课常见坑预警）。

**验证点：** 无，继续。

## 页面 F · setup()：出生登记

**标题：** setup()：这颗宝石的「出生登记」

**代码块（复制粘贴处）：**

```gdscript
func setup(gem_type: int, pos: Vector2i) -> void:
	type = gem_type
	grid_pos = pos
	set_type(gem_type)      # 立刻换上对应颜色的贴图
```

**讲师讲什么：**
- `setup` = 初始化函数。谁调用它？——下一部分 board.gd 生成宝石时会调：`gem.setup(颜色, 坐标)`
- 三行各干一件事：**记下颜色 → 记下坐标 → 立刻换贴图**（让画面跟上数据）
- 注意参数类型 `int` / `Vector2i` 和 Page D 的变量声明一一对应——Page D 造了两个「抽屉」（type、grid_pos），setup 就是把东西放进抽屉的动作

**备注框：** 为什么叫 setup 不叫 init？——名字是约定，叫什么都行；setup 是 Godot 社区常见命名，一看就懂。约定 > 个性。

**验证点：** 无，继续。

## 页面 G · set_type()：换色 = 一行代码

**标题：** set_type()：换色，就一行

**代码块（复制粘贴处）：**

```gdscript
func set_type(gem_type: int) -> void:
	type = gem_type
	_sprite.texture = gem_textures[gem_type]
```

**讲师讲什么：**
- 核心就一行：`_sprite.texture = gem_textures[gem_type]` ——把 Sprite 的贴图换成数组里的某一张
- `gem_textures[gem_type]`：**数组按下标取**。gem_type 是 0~5 的编号，数组第 0 张是红、第 1 张是蓝……**编号和贴图一一对应**——这就是 Page B 说「enum 顺序很重要」的原因！
- 所以**换色 = 改一个数字**。以后消除、换色逻辑都只改 type，画面自动跟上

**验证点：** 代码写完了！但**先别按 F5**——还差最后一步：把 6 张贴图挂进数组（下一页，对应 md Step 3.5）。
