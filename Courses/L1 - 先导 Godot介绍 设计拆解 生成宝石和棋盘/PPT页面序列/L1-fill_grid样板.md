# L1 · 代码块 PPT 页面序列样例 —— fill_grid（块5）

> **用途**：PPT 制作样板——每个代码块按这个"五步法"做成一组页面序列
> **五步法**：① 目标页 → ② 伪代码骨架页 → ③ 全貌页 → ④ 分段精讲页 → ⑤ 调用链展开 → ⑥ 运行验证页 → ⑦ 动手页
> **配套**：代码块文档 `L1-生成棋盘.md` 块5/6/7 + 逐行讲稿 `L1-逐行讲稿.md` 块5/6/7
> **导航设计**：每页角落放「代码地图」标签，学员永远知道自己在代码的哪个位置
> **⚠️ 两个全课原则**：
> 1. **伪代码先行**：任何代码块先给伪代码/骨架（宏观），再给真实代码（细节）——全貌页之前必须有缓冲
> 2. **调用链不黑盒**：被调函数的代码必须展开（先调用树，再真实代码）

## 页面 2/7 · 伪代码骨架页 ⭐（先看骨架，再看代码）

**标题：** 先看骨架：fill_grid 打算怎么干

**页面内容（伪代码 + 调用树，PPT 用树状图展示）：**

```
fill_grid（铺满棋盘）
│
├─ 1. 清场：删掉旧宝石、清空数据表
│
├─ 2. 双层循环（8 列 × 8 行 = 64 次）
│    └─ 每次调用：_spawn_gem(随机颜色, 位置)   ← 造宝石的活包给别人
│         ├─ random_gem_type()  → 返回 0~5 随机颜色编号
│         └─ 造一颗宝石（四步）：
│             ① 照图纸 instantiate 造出来
│             ② 摆到格子位置
│             ③ add_child 挂进场景
│             ④ setup 设置颜色和坐标
│         ← 返回这颗宝石
│    └─ 存进 grid 数据表
│
└─ 3. 完成：64 颗宝石，棋盘满了
```

**人话：** `fill_grid` 是包工头：自己只管清场和数数（循环），造宝石的活包给 `_spawn_gem`，颜色的事又问 `random_gem_type`。**函数就是分工：一个函数只干一件事，干不完就叫别人帮忙。**

**代码地图标签：** 📍 `board.gd` → ⑤ 棋盘生成

**讲师口播：**
「先别碰真实代码——看这个骨架。`fill_grid` 自己只做两件事：清场 + 循环。造宝石？包给 `_spawn_gem`。颜色？问 `random_gem_type`。**记住了这个骨架，下一页看真实代码就对得上号了。**」

## 页面 3/7 · 全貌页

**标题：** fill_grid —— 完整代码（有了骨架，这页不吓人）

**页面内容①（fill_grid 完整代码，供复制）：**

```gdscript
## 清空旧棋盘，重新铺满 8×8 随机宝石
func fill_grid() -> void:
	for child in get_children():        # 删掉旧宝石（防叠两层）
		child.queue_free()
	grid.clear()                        # 清空数据表
	for col in range(GRID_SIZE):        # 外层：一列一列来（8 列）
		var column: Array = []
		for row in range(GRID_SIZE):    # 内层：列里一行一行来（8 行）
			var pos := Vector2i(col, row)
			column.append(_spawn_gem(random_gem_type(), pos))  # 造一颗随机色宝石
		grid.append(column)
```

**页面内容②（对照提示）：** 跟上一页骨架对号入座——清场就是第 1 步，双层循环就是第 2 步，最后一行那两个函数调用就是骨架里的"包给别人"

**底部提示：** 这三个函数都在 `scripts/board.gd` 的「⑤ 棋盘生成」区，搜 `fill_grid` 直达

**代码地图标签：** 📍 `board.gd` → ⑤ 棋盘生成

**讲师口播：**
「现在看真实代码——是不是跟骨架一模一样？清场、双层循环、调用两个帮手。**先看骨架再看代码，就不会被一堆符号吓到。**大家把这段复制到 board.gd 里（其实项目里已经有了，我们假装它是空的）。」

## 页面 4/7 · 分段精讲① —— 清场

**标题：** 第 1 步：先清场（防止叠两层）

**页面内容（代码高亮本段，其余变灰）：**

```gdscript
func fill_grid() -> void:
	【for child in get_children():        # 删掉旧宝石（防叠两层）
		child.queue_free()
```

**讲师口播：**
「先把桌面收拾干净——删掉旧的宝石（queue_free 是 Godot 的安全删除），清空记录位置的数据表。记住原则：**画面清了，数据也清了，两边一致**。」

## 页面 5/7 · 分段精讲② —— 双层循环（核心）

**标题：** 第 2 步：双层循环 = 64 颗宝石（本课重点 ⭐）

**页面内容（代码高亮双层循环段）：**

```gdscript
func fill_grid() -> void:
	...
	【for col in range(GRID_SIZE):        # 外层：一列一列来（8 列）
		var column: Array = []
		for row in range(GRID_SIZE):    # 内层：列里一行一行来（8 行）
			var pos := Vector2i(col, row)
			column.append(_spawn_gem(random_gem_type(), pos))】  # ← 这句是黑盒，下一页拆
	...
```

**人话：**
- 外层 `for col`：一列一列来，col 从 0 数到 7（8 列）
- 内层 `for row`：每一列里一行一行来，row 从 0 数到 7（8 行）
- 两个循环套一起 = **8 × 8 = 64 次**，每次都调 `_spawn_gem` 造一颗宝石
- ⚠️ **留钩子**：`_spawn_gem(random_gem_type(), pos)` 这句到底干了啥？下一页拆！

**板书/动画：** 嵌套循环示意图（外圈=列 8 次，内圈=行 8 次），或"铺地砖"动图

**代码地图标签：** 📍 `board.gd` → ⑤ 棋盘生成 · 第 2 步/共 3 步

**讲师口播：**
「这就是生成棋盘的全部秘密：**两个循环套在一起**。外层管列 8 次，内层管行 8 次，8×8=64——每次调 `_spawn_gem` 造一颗宝石。但大家注意：**`_spawn_gem` 是什么？我们还没见过它**——下一页拆开看，这就是"函数调用"。」

## 页面 6/7 · 子函数真实代码（对号入座）

**标题：** 第 3 步：拆开黑盒——真实代码长这样

**页面内容①（random_gem_type —— 随机颜色，一行）：**

```gdscript
## 随机一种宝石类型：randi() 随机整数 % 6 → 0~5，对应 GemType 六色
func random_gem_type() -> int:
	return randi() % 6
```

**人话：** `randi()` 给个随机大数，`% 6` 取余数 → 只有 0~5 六种可能，正好对应六色（RED=0…ORANGE=5）。——就是骨架里那一行"返回随机颜色编号"。

**页面内容②（_spawn_gem —— 造一颗宝石，本课最重要概念 ⭐）：**

```gdscript
## 创建一颗宝石实例：先 add_child 进场景树，再 setup
func _spawn_gem(gem_type: int, pos: Vector2i) -> Gem:
	var gem: Gem = GEM_SCENE.instantiate() as Gem   # ① 照"图纸"复制实例（月饼模具！）
	gem.position = grid_to_world(pos)               # ② 摆到正确格子
	add_child(gem)                                  # ③ 挂到棋盘名下（必须先进树）
	gem.setup(gem_type, pos)                        # ④ 设置颜色和网格坐标
	return gem
```

**人话（四步，对应骨架里的①②③④，顺序不能乱）：**
1. `instantiate()`：照 gem.tscn 这张"图纸"造出一颗真实宝石——**月饼模具压月饼**
2. `position`：摆到它该在的格子上（坐标换算，块4 讲过）
3. `add_child`：挂到棋盘节点下，正式"出现在游戏里"（必须先做这步，setup 要用的子节点得先进树）
4. `setup`：告诉它你是什么颜色、在第几格

**代码地图标签：** 📍 `board.gd` → ⑤ 棋盘生成 · 子函数（对照骨架）

**讲师口播：**
「对照骨架看：`random_gem_type` 就是那行"返回 0~5 随机编号"；`_spawn_gem` 的四步就是树里的①②③④。**先看骨架再对细节，代码就不迷路了。**这就是本课最重要的概念：**场景实例化**——64 颗宝石 = 同一张图纸造了 64 次。」

## 调用链原则（全课通用）

**任何一个函数块的 PPT 页面序列，必须包含它调用的所有函数**，且按固定顺序：**先伪代码骨架（宏观）→ 真实代码全貌 → 精讲 → 子函数展开**：

- 直接调用（同文件）：附代码，精讲页展开（如 fill_grid → _spawn_gem → random_gem_type）
- 跨文件调用：附代码 + 标注文件位置（如 main.gd → board.try_swap，见 L2 处理）
- 特殊函数：第一次出现就讲透；再次出现只标"📍 见块X"
- **每个调用链配一份伪代码调用树**（缩进树/树状图：谁调谁、数据怎么走）——放在全貌页**之前**

**原因**：零基础学员对"黑盒调用"没有任何直觉——你写 `_spawn_gem(...)` 他不认识，不展开讲，后面全断；直接甩真实代码又陷进细节。**伪代码骨架先行 + 真实代码对号入座，宁可多一页，不要黑盒。**
