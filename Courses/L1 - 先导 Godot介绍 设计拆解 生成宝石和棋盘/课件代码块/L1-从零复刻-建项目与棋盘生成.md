# L1 课件代码 · 从零复刻手册（新建项目 → 8×8 棋盘）

> **定位**：对齐官方教程（Dodge the Creeps）模式——学员**从零新建项目**，按步骤操作场景、贴代码块，逐步复刻出棋盘
> **分工**：设计拆解（宝开历史/玩法循环/体验保护）由 pppig 负责；本文档只覆盖「从零到棋盘」的操作步骤与代码
> **代码来源**：教学版 v3.2（`scripts/board.gd` / `scripts/gem.gd` / `scenes/gem.tscn`）——函数名、变量名逐字对齐，**学员写的代码与成品同构**，L2/L3/L4 可直接增量接续
> **本课终点**：F5 看到 8×8 彩色棋盘（无初始三消）→ 改 `GRID_SIZE` 8→10 棋盘变大（人生第一次改代码）
> **预计时长**：操作 + 敲码约 55~65min（不含设计拆解环节）

---

## 0. 讲师视角：本课代码 = 成品的哪些部分

学员本课结束时的两个脚本，是成品脚本的**子集**（不是简化改写，是裁剪）：

| 学员本课写的 | 成品对应 | 后续课时 |
|---|---|---|
| `gem.gd`：enum / 贴图 / setup / set_type | gem.gd ①② 区 | set_selected 遮罩 → L2；动画三件套 → L3 |
| `board.gd`：常量 / _ready / 坐标 / 生成三件套 | board.gd ①(部分)②④⑤ 区 | world_to_grid / 判定正式版 → L2；结算/下落 → L3 |
| `board.gd`：简化版 `find_matches` | ⑥ 区的**去分组版** | L2 升级为正式分组版（只差一个「分组」概念） |
| `board.gd`：`ensure_no_initial_matches` + `reset_game` | ⑦ 区（不含 has_moves） | ensure_has_moves 防死局 → L2 加 |

**刻意不引入（概念最小化，用到才讲）：** 信号 signal（L4）、score 计分（L3）、`world_to_grid`（L2 输入）、`ensure_has_moves`（L2）、动画（L3）。

**为什么「简化版 find_matches」：** 完整正式版要讲「分组 + 去重」两个概念，是第 2 课 30min 精讲的核心算法。L1 只需要「能查出有没有三连」来排除初始三消，所以给一个去分组的最小版。L2 升级时**只加一个「分组」概念**，改动量极小，教学叙事顺滑。

## 1. Step 0 · 新建项目 + 项目设置（约 5min）

**操作步骤：**
1. 打开 Godot 4.7 → 项目管理器 → **New Project**
2. 项目名：`match3`（或任意英文名）；路径自选；渲染器选 **Compatibility**（兼容老电脑，和成品一致）；**Create**
3. 打开项目后，菜单 **项目 → 项目设置**，改 3 处：
   - **Display → Window**：Viewport Width `640`，Viewport Height `720`（成品窗口尺寸）
   - （可选）**Rendering → Renderer**：确认是 `gl_compatibility`
   - **Application → Run**：Main Scene 暂不设（Step 4 建好 main.tscn 再回来设）

**验证点：** 项目能打开，编辑器四面板（场景/节点/检查器/文件系统）正常。

**讲师讲什么：** 窗口尺寸就是「游戏的画布」；Compatibility 是轻量渲染器——2D 游戏用它就够。

## 3. Step 2 · 搭 gem.tscn（宝石「图纸」，约 10min）

**操作步骤（场景树从空开始搭）：**

1. 菜单 **场景 → 新建场景** → 根节点选 **Node2D** → 命名 `Gem` → 保存为 `scenes/gem.tscn`
2. 选中 `Gem`，点工具条 **+（添加子节点）** → 添加 **Sprite2D**，命名 `Sprite`
3. 在 **检查器** 里把 `assets/sprites/gems/gem_red.png` **拖进** Sprite 的 **Texture 槽**（这就是「贴图=挂资源」）
   - 勾掉 **Centered**（贴图左上角对齐格子，方便定位）
   - **Scale** 设 `(1.2308, 1.2308)`（52px 贴图 → 64px 格子）
4. 再添加子节点 **ColorRect**，命名 `SelectMask`：
   - Offset Right `64`、Offset Bottom `64`（铺满一格）
   - Color 白色 + Alpha `0.45`（半透明）
   - **Mouse Filter = Ignore**（下拉选 Ignore，别挡鼠标）
   - **Visible 勾掉**（默认隐藏，第 2 课选中时才亮）
5. 选中 `Gem` 根节点 → 检查器 **新建脚本** → **Inherits 保持 Node2D，模板选默认/Empty** → 保存到 `scripts/gem.gd`（脚本会自己挂上）

**场景树长这样：**
```
Gem (Node2D) [gem.gd]
├── Sprite (Sprite2D)        # texture=gem_red.png, scale 1.2308
└── SelectMask (ColorRect)   # 64×64 半透明白, 隐藏, mouse_filter=2
```

**讲师讲什么：**
- 一个 .tscn 文件 = 一颗宝石的「图纸」：根节点 + 两个子节点
- **贴图是资源不是代码**：Texture 槽拖 PNG，改图不用动代码
- SelectMask 先埋伏笔：选中高亮用的，第 2 课见

## 4. Step 3 · gem.gd（宝石脚本，约 10min）

新建脚本后，把内容**整个替换**成下面这段（L1 版）：

```gdscript
extends Node2D
## gem.gd —— 一颗宝石长什么样（L1 版：类型 + 贴图）
class_name Gem    # 声明全局类型：board.gd 里才能写 `var gem: Gem`

## 六种宝石颜色（枚举 = 一组有名字的整数常量）
## RED=0, BLUE=1, GREEN=2, YELLOW=3, PURPLE=4, ORANGE=5
enum GemType { RED, BLUE, GREEN, YELLOW, PURPLE, ORANGE }

## 六色贴图数组：在 gem.tscn 里按 enum 顺序挂好 6 张 PNG
@export var gem_textures: Array[Texture2D] = []

## 当前宝石类型（默认红色）
var type: int = GemType.RED
## 网格坐标 (col, row)——它在棋盘的哪一格
var grid_pos: Vector2i = Vector2i.ZERO

## @onready：节点进场景树后才取子节点
@onready var _sprite: Sprite2D = $Sprite
@onready var _select_mask: ColorRect = $SelectMask

## 初始化：设置类型 + 网格坐标（由 board._spawn_gem 创建时调用）
func setup(gem_type: int, pos: Vector2i) -> void:
	type = gem_type
	grid_pos = pos
	set_type(gem_type)      # 立刻换上对应颜色的贴图

## 更换类型：从数组里取对应颜色的贴图
func set_type(gem_type: int) -> void:
	type = gem_type
	_sprite.texture = gem_textures[gem_type]
```

**讲师讲什么：**
- `enum` = 给颜色起名字的编号：写 `GemType.RED` 比写 `0` 好懂
- `type` 存编号（0~5），`set_type` 用它去贴图数组取图 → **换色 = 一行代码**
- `@onready`：等节点进树才取子节点 → 所以创建宝石必须「先进树再 setup」（Step 6 呼应）
- `_select_mask` 这行先声明但没用到？—— 预留给第 2 课选中功能（可先删，也可留着注释）

> ⚠️ **与成品的差异说明**（讲师知道即可）：成品 gem.gd 还有 `set_selected` 遮罩和交换/消除/下落动画，本课不写，第 2/3 课增量加。

### Step 3.5 · 回填贴图数组（约 2min）——让「六色」真正生效 ⭐

> ⚠️ **为什么现在才挂？** Part 2 搭场景时不提前引入数组概念；刚写完 gem.gd，正好认识 `@export` 数组 = 场景里能填的「贴图槽位」。

**操作步骤：**

1. 回到 `gem.tscn` 场景，选中 `Gem` 根节点
2. 检查器里找到 `gem_textures`（Array[Texture2D]）→ 展开 → **添加 6 个元素**
3. **按 enum 顺序逐个拖入贴图**（顺序错了颜色就会错位）：
   - 元素 0 → `gem_red.png`（RED=0）
   - 元素 1 → `gem_blue.png`（BLUE=1）
   - 元素 2 → `gem_green.png`（GREEN=2）
   - 元素 3 → `gem_yellow.png`（YELLOW=3）
   - 元素 4 → `gem_purple.png`（PURPLE=4）
   - 元素 5 → `gem_orange.png`（ORANGE=5）

**讲师讲什么：**

- `@export` 数组 = 场景检查器里能填的「贴图槽位」——**代码声明槽位，场景负责填图**，改图不用动代码（延续「贴图是资源不是代码」）
- **顺序 = enum 编号**：`set_type` 里 `gem_textures[gem_type]` 一行换色，靠的就是「数组下标和颜色编号一一对应」
- 这是「数据（编号）与表现（贴图）分离」的第一次接触

**验证点：** 本步先不 F5——主场景还没建，F5 会提示没有主场景（属正常）。数组已挂好，等 Step 6 第一次 F5 就是成功画面。

## 6. Step 5 · board.gd（棋盘脚本，约 25min，分 5 小块贴）

### 块 B1 · 常量与数据（board.gd 开头）

```gdscript
extends Node2D
## board.gd —— 棋盘（L1 版：生成 8×8 无初始三消的棋盘）

## 棋盘规格：8 列 × 8 行
const GRID_SIZE := 8
## 每格边长（像素），棋盘总尺寸 = 8 × 64 = 512
const CELL_SIZE := 64

## 宝石「图纸」——instantiate() 复制出真实宝石（场景实例化）
const GEM_SCENE := preload("res://scenes/gem.tscn")

## 二维数组 grid[col][row]：第一维是列，第二维是行
## 元素是 Gem（有宝石）或 null（空位）
var grid: Array = []
## 棋盘左上角的世界坐标（用于居中）
var origin: Vector2 = Vector2.ZERO
```

**讲师讲什么：** `const` = 常量（不能改）；`grid[col][row]` **先列后行**（和「先横后竖」的直觉相反，重点强调）；`preload` 提前加载图纸。

### 块 B2 · 居中 + 坐标换算

```gdscript
func _ready() -> void:
	_compute_origin()
	reset_game()    # L1 直接生成棋盘（成品是「点开始才生成」，L4 讲完 HUD 再改回）

## 让 512×512 棋盘在窗口（640×720）中居中
func _compute_origin() -> void:
	var board_pixels := GRID_SIZE * CELL_SIZE   # 512
	var vp := get_viewport_rect().size          # 窗口尺寸 (640, 720)
	origin = Vector2(
		(vp.x - board_pixels) / 2.0,    # (640-512)/2 = 64
		(vp.y - board_pixels) / 2.0     # (720-512)/2 = 104
	)

## 网格坐标 → 世界坐标：第 (col,row) 格的左上角像素位置
func grid_to_world(pos: Vector2i) -> Vector2:
	return origin + Vector2(pos.x, pos.y) * CELL_SIZE
```

**讲师讲什么：**
- 为什么需要换算：格子是「逻辑坐标 (col,row)」，屏幕要「像素坐标」
- 伪代码：`像素位置 = 棋盘左上角 + 格子坐标 × 格子大小`
- `grid_to_world(0,0)` = 左上角第一格；`(7,7)` = 右下角
- ⚠️ 注意 `_ready` 里直接调了 `reset_game()`——本课没有开始按钮，所以一运行就生成（成品是点开始才生成，L4 改回）

### 块 B3 · 生成三件套（本课核心 ⭐）

```gdscript
## 随机一种宝石类型：randi() 随机整数 % 6 → 0~5，对应 GemType 六色
func random_gem_type() -> int:
	return randi() % 6

## 清空旧棋盘，重新铺满 8×8 随机宝石
func fill_grid() -> void:
	for child in get_children():        # 删掉棋盘上所有旧宝石节点
		child.queue_free()
	grid.clear()                        # 清空数据表
	for col in range(GRID_SIZE):        # 外层循环：逐列（8 列）
		var column: Array = []
		for row in range(GRID_SIZE):    # 内层循环：该列逐行（8 行）
			var pos := Vector2i(col, row)
			column.append(_spawn_gem(random_gem_type(), pos))
		grid.append(column)

## 创建一颗宝石：先 add_child 进场景树，再 setup（顺序不能反！）
func _spawn_gem(gem_type: int, pos: Vector2i) -> Gem:
	var gem: Gem = GEM_SCENE.instantiate() as Gem   # 按图纸复制实例
	gem.position = grid_to_world(pos)               # 摆到正确格子
	add_child(gem)                                  # 挂到棋盘节点下（必须先进树）
	gem.setup(gem_type, pos)                        # 设置颜色和网格坐标
	return gem
```

**讲师讲什么：**
- **双层 for = 64 次**：8 列 × 8 行，每次一颗——「生成棋盘」的全部秘密
- **场景实例化（本课最重要概念）**：gem.tscn 是图纸，`instantiate()` 照图纸造产品；月饼模具 → 64 个月饼
- 三步顺序：定位置 → 进树 → setup（呼应 gem.gd 的 @onready）
- 先 `grid.clear()` + 删旧节点：重复调用不会叠两层

### 块 B4 · 临时判定 find_matches（简化版，L2 升级 ⚠️）

```gdscript
## 找出所有「连续 ≥3 个同色」的宝石（L1 简化版：不分组）
## ⚠️ 第 2 课升级为正式「分组版」——只加一个概念，见大纲 L2
func find_matches() -> Array:
	var matched: Array = []
	# 横向：逐行扫，找连续同色段
	for row in range(GRID_SIZE):
		var run_start := 0
		while run_start < GRID_SIZE:
			var gem0: Gem = grid[run_start][row] as Gem
			if gem0 == null:                # 空位跳过
				run_start += 1
				continue
			var run_type: int = gem0.type   # 这一段连续段的颜色
			var run_end := run_start + 1
			while run_end < GRID_SIZE:      # 向右延伸，直到颜色不同
				var g: Gem = grid[run_end][row] as Gem
				if g == null or g.type != run_type:
					break
				run_end += 1
			if run_end - run_start >= 3:    # 连续 ≥3 才算匹配
				for c in range(run_start, run_end):
					_add_unique(matched, grid[c][row] as Gem)
			run_start = run_end             # 从这段之后继续找
	# 纵向：逐列扫，逻辑同上（col/row 互换）
	for col in range(GRID_SIZE):
		var run_start := 0
		while run_start < GRID_SIZE:
			var gem0: Gem = grid[col][run_start] as Gem
			if gem0 == null:
				run_start += 1
				continue
			var run_type: int = gem0.type
			var run_end := run_start + 1
			while run_end < GRID_SIZE:
				var g: Gem = grid[col][run_end] as Gem
				if g == null or g.type != run_type:
					break
				run_end += 1
			if run_end - run_start >= 3:
				for r in range(run_start, run_end):
					_add_unique(matched, grid[col][r] as Gem)
			run_start = run_end
	return matched

## 去重：同一颗宝石不重复进数组（可能同时属于横/纵匹配）
func _add_unique(arr: Array, gem: Gem) -> void:
	if gem != null and not arr.has(gem):
		arr.append(gem)
```

**讲师讲什么（伪代码先行，不逐行念）：**
- 思路一句话：**横着扫一遍、竖着扫一遍，把「连续 ≥3 个同色」的宝石都收进来**
- 「段（run）」：从一颗开始向右数，数到颜色变或越界为止；够 3 颗就整段收走，然后从段尾接着找（每颗只扫一次）
- 这版代码学员**照抄即可**，不要求当场读懂——第 2 课会精讲这个算法 30min 并升级

### 块 B5 · 防初始三消 + 开局（「不重复」的关键 ⭐）

```gdscript
## 开局：铺满棋盘 → 排除初始三消（本课只有这两步，L2 再加防死局）
func reset_game() -> void:
	fill_grid()                    # 铺满 64 颗随机宝石
	ensure_no_initial_matches()    # 开局不能自带三消（否则一开场就消除，像 bug）

## 排除初始三消：有匹配就把那颗换随机色，直到棋盘稳定
func ensure_no_initial_matches() -> void:
	var safety := 0
	while safety < 100:
		var matches := find_matches()      # 找出当前所有匹配
		if matches.is_empty():
			return                         # 没有匹配了，稳定
		for gem in matches:                # 有匹配 → 每颗换随机色
			(gem as Gem).set_type(random_gem_type())
		safety += 1
	push_warning("ensure_no_initial_matches: 超过安全次数仍有匹配")
```

**讲师讲什么：**
- **为什么需要它（呼应设计拆解「体验保护」）**：纯随机可能铺出「红红红」——虽然现在还没消除逻辑看不出问题，但第 2 课一加上交换消除，开局就会自动消一排，学员会以为写坏了
- 解法：铺完 → 查匹配 → 有就换色 → 再查，循环到没有为止（`while` + 安全阀 `safety < 100` 防死循环）
- **第 2 课预告**：`find_matches` 是核心算法，下节课精讲

## 8. 常见坑（讲师备注）

| 宝石看不见 | ColorRect/Sprite 没设 size/贴图没挂；检查 Sprite 的 texture 槽 |
| 位置不对 | 忘勾 Sprite 的 Centered，或忘设 scale 1.2308 |
| 报错 `Cannot infer type` / Variant | 复制代码时丢了 `as Gem` 或 `:=` 类型标注；`grid_to_world` / `_spawn_gem` 这类函数名别手改 |
| 报错 `Index out of bounds` | gem_textures 数组没挂满 6 张（Step 3.5）或拖入顺序没按 enum |
| 改完没生效 | 改代码必须 F5 重新运行；脚本保存（Ctrl+S） |
| 运行时 0 颗宝石 | 忘了把 main.tscn 设为主场景，或 Board 上没挂 board.gd |
| 开局有 3 连 | 说明 `ensure_no_initial_matches` 没被调（reset_game 里）或没写完 |
