> **用途**：PPT 放代码，讲师按本讲稿的「人话」栏念——每一行代码对应一句大白话
> **配套**：代码块文档 `L1-生成棋盘.md`（PPT 取代码用）；本讲稿（嘴上说什么用）

> **核心比喻（全课反复用）**：**场景 = 图纸，instantiate = 照着图纸造产品（月饼模具）**

## 块1 · gem.tscn 宝石场景（实操①：拆解宝石）

> PPT 显示 gem.tscn 完整内容（见 L1-生成棋盘.md 块1），讲师对着场景树讲

| 代码/节点 | 人话（照读） |
|---|---|
| `[node name="Gem" type="Node2D"]` | 「一颗宝石，本质上就是屏幕上的一个"点"——它有位置、能旋转、能缩放。我们所有的宝石都是这个点变出来的。」 |
| `[node name="Sprite" type="Sprite2D"]` | 「Sprite2D 是"显示图片"的节点。它的作用就一句话：**把我挂的这张图画出来**。」 |
| `texture = ...gem_red.png` | 「看这里——贴图不是代码画的，是**直接拖一张 PNG 图片到这个槽里**。就像手机壁纸：你换一张图，它显示就变了。」 |
| `scale = Vector2(1.2308, 1.2308)` | 「这张图本来是 52 像素的小图，我们把它放大 1.23 倍，正好变成 64 像素——跟棋盘格子一样大。这个数字已经算好写死了，不用管。」 |
| `[node name="SelectMask" ...]` | 「这是个半透明的白色方块，现在是**藏起来**的（visible=false）。以后选中宝石时它会亮起来——第 2 课才用到，先记住它存在。」 |
| `gem_textures = Array[...]` | 「这行是给脚本里 `gem_textures` 数组按顺序塞了 6 张图：红蓝绿黄紫橙。**顺序不能乱**，因为代码按编号取图：0 号=红，1 号=蓝……」 |

**板书建议：** 画一个宝石节点树（Gem → Sprite / SelectMask），标"Sprite=显示图，SelectMask=选中高亮"。

## 块2 · gem.gd 类型与贴图

| 代码 | 人话（照读） |
|---|---|
| `class_name Gem` | 「给这个脚本起个名字叫 Gem。起了名，别的脚本就能拿它当"类型"用——就像说"这是一颗宝石"，Godot 就知道你指的是这种节点。」 |
| `enum GemType { RED, BLUE, ... }` | 「枚举 = **给数字起名字**。代码里 0 代表红、1 代表蓝，但写 `GemType.RED` 比写 `0` 好懂一万倍。记住：**RED=0，BLUE=1，GREEN=2……ORANGE=5**，一共 6 个。」 |
| `@export var gem_textures: Array[Texture2D]` | 「`@export` 的意思是：**这个变量能在场景面板里直接填**——刚才块1里那 6 张图就是这么挂进来的。脚本不写死图片，图是外面喂进来的。」 |
| `var type: int = GemType.RED` | 「这颗宝石当前是什么颜色？存的是编号（默认红色=0）。」 |
| `var grid_pos: Vector2i` | 「它在棋盘的第几列、第几行？比如 (3,5) = 第 3 列第 5 行。**注意先列后行**，跟数学坐标(x,y)一个习惯，但跟"第几行第几列"的说法相反——这是最容易搞混的地方。」 |
| `@onready var _sprite: Sprite2D = $Sprite` | 「`$Sprite` = 找自己名下的 Sprite 子节点。`@onready` = **等进了场景再找**。为什么？没进场景时子节点还不存在，提前找会扑空。」 |
| `func setup(...)` | 「**出生函数**：一颗宝石被造出来时调用一次——记下颜色、记下位置，然后立刻换上对应颜色的贴图。」 |
| `func set_type(gem_type)` | 「**换颜色 = 换贴图**：`gem_textures[3]` 就是第 3 张图（黄色）。所以"把宝石变黄"在代码里就是一行：`set_type(3)`。」 |

**板书建议：** 写 `gem_textures[0]=红图 [1]=蓝图 [2]=绿图 [3]=黄图 [4]=紫图 [5]=橙图` 的对应表。

## 块3 · 棋盘常量与数据

| 代码 | 人话（照读） |
|---|---|
| `const GRID_SIZE := 8` | 「**常量** = 定死了不能改的数。8 = 棋盘 8 列 8 行。记住这一行——**等会儿实操就是改它**。」 |
| `const CELL_SIZE := 64` | 「每格 64 像素。8×64 = 512，整个棋盘是 512×512 像素的正方形。」 |
| `const GEM_SCENE := preload(...)` | 「`preload` = 提前把 gem.tscn 这张"图纸"拿在手里。等会儿要用 `instantiate()` 照着它造宝石。**图纸提前备好，用的时候直接造。**」 |
| `var grid: Array = []` | 「**棋盘数据表**：一个二维数组，`grid[列][行]` 存那颗宝石。格子是空的就存 null。注意：**这张表是"数据"，屏幕上的是"画面"，两者要分清**——以后所有规则都查这张表。」 |
| `var origin: Vector2 = Vector2.ZERO` | 「棋盘左上角在屏幕上的位置。先记 0，后面 `_compute_origin` 会算它。」 |

**板书建议：** 画一个 8×8 方格图，标 `grid[0][0]` 在左上角，`grid[7][7]` 在右下角。

## 块4 · 坐标换算（棋盘怎么摆到屏幕中间）

| 代码 | 人话（照读） |
|---|---|
| `func _compute_origin()` | 「**算棋盘左上角放哪**。窗口是 640×720，棋盘是 512×512，要居中。」 |
| `(vp.x - board_pixels) / 2.0` | 「居中公式：**（窗口宽 - 棋盘宽）÷ 2 = 左边留多少空白**。640-512=128，÷2=64，所以左边空 64 像素。上下同理，104 像素。」 |
| `func grid_to_world(pos)` | 「**逻辑坐标 → 屏幕坐标**。游戏里我们只说"第 3 列第 5 行"，但屏幕上得知道"第 3 列第 5 行的左上角在哪个像素位置"。公式：`左上角 + 格子号 × 格子大小`。」 |

**板书建议：** 写公式 `屏幕位置 = origin + 格子坐标 × 64`，配一张格子图标注。

## 块5 · 生成棋盘 fill_grid（核心块 ⭐）

> 讲师先讲伪代码（PPT 放伪代码）：`for 每列: for 每行: 在(col,row)放一颗随机色宝石`，再对照真代码

| 代码 | 人话（照读） |
|---|---|
| `for child in get_children():` | 「先**清场**：把棋盘上已有的宝石节点全删掉。防止重开一局时叠出两层棋盘。」 |
| `child.queue_free()` | 「`queue_free` = 安全删除。说"删"不是立刻删，是等这一帧结束再删——Godot 的习惯写法，避免删到一半出错。」 |
| `grid.clear()` | 「数据表也清空。**画面清了，数据也清了，两边一致。**」 |
| `for col in range(GRID_SIZE):` | 「**外层循环：一列一列来**。col 从 0 数到 7——想象你站在棋盘最左边，一列一列往右铺。」 |
| `var column: Array = []` | 「先拿个**空袋子**，准备装这一列的 8 颗宝石。」 |
| `for row in range(GRID_SIZE):` | 「**内层循环：这一列里一行一行来**。row 从 0 数到 7——从最上面往下铺。」 |
| `var pos := Vector2i(col, row)` | 「记下"现在铺到第几列第几行"。」 |
| `column.append(_spawn_gem(...))` | 「**造一颗宝石放进去**（造的过程看块7）。这一行执行 64 次——8 列 × 8 行。」 |
| `grid.append(column)` | 「这一列铺完了，把整袋宝石存进棋盘数据表。」 |

**口播串讲（连贯版）：** 「**铺棋盘 = 两个循环套一起**。外层管列（8 次），内层管行（8 次），一共 8×8=64 次，每次造一颗宝石。这就是为什么改 GRID_SIZE 会改变宝石数量——**改 10 就是 10×10=100 颗**。」

**板书建议：** 写 `8×8=64`，画两层循环的嵌套示意图（外圈=列，内圈=行）。

## 块7 · 创建单颗宝石 _spawn_gem（场景实例化 ⭐ 本课最重要）

| 代码 | 人话（照读） |
|---|---|
| `GEM_SCENE.instantiate()` | 「**照着图纸造产品**——这是 Godot 最核心的概念！gem.tscn 是图纸，`instantiate()` 是造出一个真实的宝石节点。64 颗宝石 = 同一张图纸造 64 次。」 |
| `as Gem` | 「告诉 Godot：「我造出来的这个东西，就是 Gem 类型的宝石」——不然它不知道这是啥。」 |
| `gem.position = grid_to_world(pos)` | 「**先定位置**：把宝石放到它该在的格子上（用块4的坐标换算）。」 |
| `add_child(gem)` | 「**再挂到棋盘名下**（进场景树）。这一步之后宝石才真正"出现在游戏里"。」 |
| `gem.setup(gem_type, pos)` | 「**最后初始化**：告诉它你是什么颜色、在哪格（调块2的 setup）。」 |
| `return gem` | 「把造好的宝石交回去，让 fill_grid 存进数据表。」 |

**口播串讲（连贯版）：** 「造宝石的顺序是死的：**定位置 → 进场景 → 初始化**，不能乱。为什么？因为 setup 里要用的子节点（Sprite）得先进了场景才找得到——就是块2里那个 @onready。**月饼模具类比**：图纸是模具，instantiate 是压月饼，add_child 是把月饼摆到盘子上。」

**板书建议：** 画 三步流程图：`instantiate（照图纸造）→ add_child（摆上桌）→ setup（上色）`。

## 块8 · 去初始三消 ensure_no_initial_matches（"不重复"关键 ⭐）

> 先讲"为什么"：纯随机可能铺出「红红红」连一起 → 游戏一开局就自动消除 → 学员以为代码坏了

| 代码 | 人话（照读） |
|---|---|
| `while safety < 100:` | 「**反复检查**，最多查 100 轮（安全阀，防死循环——万一怎么都排不干净，别让游戏卡死）。」 |
| `var matches := find_matches()` | 「**检查现在有没有三消**：find_matches 会找出所有"连续 3 个同色"的宝石。这个函数第 2 课细讲，现在只要知道它"能查"。」 |
| `if matches.is_empty(): return` | 「**没有三消了，完美，收工。**」 |
| `for gem in matches:` | 「有的话，**把每一颗三消里的宝石**……」 |
| `(gem as Gem).set_type(random_gem_type())` | 「**……换成一个随机新颜色**。换完可能又产生新的三消，所以回到 while 再查一遍。」 |
| `push_warning(...)` | 「100 轮都没排干净就报警告（理论上几乎不会发生，防御性代码）。」 |

**口播串讲（连贯版）：** 「逻辑就是一个循环：**铺完 → 查有没有三连 → 有就换色 → 再查 → 直到没有**。就像铺地砖，发现三块同色的连一起了，就抽一块换掉，换完再检查一遍，直到整面墙没有三连——这样开局才"干净"，不会一打开游戏就自己消消乐，看起来像 Bug。」

**板书建议：** 写循环三行：`铺完 → 查三连 → 有就换色（循环）`。
