## 第1课时：引擎入门 + 基础搭建（对应 M1）

**教学目标：** 装好环境，理解场景/节点/实例化，做出 8×8 彩色网格

| 环节 | 内容 | 时长 |
|------|------|------|
| 开场 | 课程介绍、成品展示（最终三消游戏 demo 视频/截图） | 5min |
| 环境安装 | Godot 4.7 下载安装（官网/Steam）、首次启动、创建项目 | 15min |
| 编辑器界面 | 场景/节点/检查器/文件系统四大面板 | 15min |
| 场景与节点 | 场景树、节点类型（Node2D/Label/Button）、父子关系、**场景实例化概念** | 15min |
| 动手：网格渲染 | 创建 gem.tscn 宝石场景 + Board 节点，实例化生成 8×8 彩色方块 | 40min |
| 小结 + Q&A | 回顾：什么是节点、什么是数组、循环生成、实例化 | 10min |

**本课知识点：**
- 节点与场景树（游戏 = 节点的树）
- **场景实例化**：gem.tscn 是独立场景，`preload + instantiate()` 生成 64 个实例（官方 Step by step 核心概念）
- **宝石视觉二选一叙事**：课上先用 ColorRect 纯色占位（聚焦逻辑），成品再换 AnimatedSprite2D 贴图（`assets/sprites/gems/gem_bomb_rainbow.png`，六色行号 BLUE0/GREEN3/ORANGE6/PURPLE9/RED12/YELLOW18）
- 二维数组 `grid[col][row]`
- `for` 循环生成 64 个宝石节点
- 随机数：宝石颜色用 `randi()` 随机生成
- 坐标换算（网格坐标 → 像素坐标）；`origin` 居中棋盘
- **开局防自消**：`ensure_no_initial_matches`——生成后检查无初始三消（避免学员误以为游戏 bug）
- **命名规范**：节点/类 PascalCase、变量/函数 snake_case、常量 ALL_CAPS（官方风格指南）

**演示代码：** `gem.tscn` + `gem.gd`（宝石场景）+ `board.gd`（实例化+网格生成）

**课后作业：** 把网格改成 6×6 或 10×10；换一种颜色

**常见坑：** 节点位置设置用 `position` 不是 `global_position`；**ColorRect 挂在 Node2D 下必须显式设 `size`，否则不可见**；二维数组越界（0~7）；**先 `add_child` 再 `setup`**（@onready 依赖进树）

## 第2课时：交互与核心机制（对应 M2）

**教学目标：** 能点选/拖拽交换宝石、取消选中、三消判定、开局防死局、消除计分

| 环节 | 内容 | 时长 |
|------|------|------|
| 回顾 + 作业讲评 | 上节课网格、答疑 | 10min |
| 输入处理 | 鼠标点击检测、坐标换算回网格 | 20min |
| 选中与交换交互 | 点选交换、**拖拽交换**、**再点取消选中**（交互规则表） | 30min |
| 核心算法：三消判定 | 行/列扫描，连续≥3 同色标记 | 30min |
| 开局防死局 | `ensure_has_moves`：枚举相邻交换 + find_matches 验证可行步 | 10min |
| 消除与计分 | 移除宝石、分数计算（3个=30，每多1个+10） | 10min |
| 小结 + Q&A | 回顾：状态、数组遍历、匹配算法思路 | 10min |

**本课知识点：**
- 鼠标输入：`_unhandled_input` + `get_global_mouse_position()` 换算（比 event.position 更稳，兼容后续相机/拉伸）
- **InputMap 输入动作**：官方推荐用「动作（action）」而非直接监听按键——可重映射、语义清晰；建 `click` 动作绑定鼠标左键
- 状态机雏形（IDLE / SELECTED）
- **选中反馈用半透明白遮罩（SelectMask），不要用 scale 放大**——放大易挤占邻格观感差（实际迭代教训）
- **交互规则表（v2.1 正式化）**：IDLE 点击宝石→选中；SELECTED 点击已选中→**取消选中回 IDLE**；点击相邻→交换；点击非相邻→换选；选中后按住拖动→**拖拽交换**；原地松开→保持选中
- **拖拽交换**（v2.1 正式教学点）：`InputEventMouseMotion` + 位移阈值 `DRAG_SWAP_THRESHOLD = 28px` 判定方向 + 视觉跟随限一格；「按下+位移」的**连续输入**与「点选+交换」的**离散输入**并存，是交互层核心概念
- 匹配检测算法：逐行逐列扫描 + 边界判断
- 交换合法性校验 + 无匹配回滚
- **开局防死局 `ensure_has_moves`**（v2.1）：遍历相邻交换对、模拟交换后用 find_matches 验证——**find_matches 的逆向应用**；无解则重排（与 M1 的 `ensure_no_initial_matches` 是兄弟函数，M5 提示系统的 `find_hint_swap` 同族）
- **规则写死：仅「交换后产生匹配」算成功并扣步，弹回不扣**
- **GDScript 类型与「警告当错误」（重要新增）**：项目开启警告当错误后，`abs()` 返回 Variant 会直接编不过——用 `absi`；`instantiate()` 需 `as Gem` 显式转换；`preload("board.gd")` 作脚本类型。**学员抄 abs 会踩，必须讲**

**演示代码：** `main.gd`（输入分发 + 状态机 + 拖拽 + 再点取消）+ `board.gd`（try_swap / find_matches / has_moves / ensure_has_moves）+ `gem.gd`（选中遮罩）

**课后作业：** 匹配长度改成 4 连才算消除；加分规则自己改；尝试自己实现 `has_moves()`（提示：枚举相邻交换对，复用 find_matches）

**常见坑：** 数组越界（row/col 0~7）；交换后忘记回滚导致状态错乱；拖拽 motion 事件要在 `_dragging` 为 true 时才响应（否则松开后拖不动）；「再点取消」分支不要误触发拖拽启动；`abs` 在警告当错误下编不过（要用 `absi`）

## 第3课时：游戏循环（对应 M3）

**教学目标：** 消除→下落→填充→连锁的完整循环 + 状态锁

| 环节 | 内容 | 时长 |
|------|------|------|
| 回顾 + 作业讲评 | 上节课算法、答疑 | 10min |
| 拆文件：board_resolve.gd | 为什么拆（board.gd 膨胀）、RefCounted 辅助类 | 10min |
| 下落与填充 | 空位上方宝石下落、顶部生成新宝石 | 25min |
| 连锁检测 | 填充后自动再判定、循环直到无匹配 | 20min |
| 状态机完善 | SWAPPING / RESOLVING 期间锁输入 | 20min |
| 动画 | Tween 平滑移动/淡出（交换动画补全） | 15min |
| 小结 + Q&A | 回顾：游戏循环、状态机为什么重要 | 10min |

**本课知识点：**
- **拆文件动机（教学点）**：board.gd 超 150 行 → 拆出 `board_resolve.gd`（RefCounted 辅助类：resolve_board / clear_matches / fall_and_refill），Tween 建在 Board 上便于一次 await
- 动画：Tween（`create_tween()` 移动/淡出）
- **动画串行：`await tween.finished` 顺序执行，禁止并发 Tween**（并发会导致宝石位置与 grid 数据不同步）；同阶段多颗并行、阶段之间串行
- 下落算法：逐列自下而上压实；`FALL_PER_CELL = 0.08` 按格数近似恒速
- 连锁：`resolve_board()` while 循环直到棋盘稳定；**连锁倍率：第 n 次消除 ×n**
- 完整状态机：WAITING / IDLE / SELECTED / SWAPPING / RESOLVING / GAME_OVER，动画期间锁输入
- **步数策略（重要变化）**：M3 可先做「强制 20 步」演示教学，**但成品为可选（默认无限步）**——`moves_limited` 开关，MovesLabel 显示 ∞

**演示代码：** `board_resolve.gd`（resolve_board 连锁管道）+ `board.gd`（扣步/信号）+ 动画方法

**课后作业：** 给连锁加分数倍率（连锁次数 ×2 加分）；把限步打开跑一局

**常见坑：** Tween 并发导致宝石位置错乱（必须 await 串行）；下落顺序必须从列底向上扫；交换/消除/下落各一个 async 函数

## 第4课时：UI 与发布（对应 M4）

**教学目标：** 完整 HUD、素材、音效 BGM、胜负判定、导出 exe

| 环节 | 内容 | 时长 |
|------|------|------|
| 回顾 | 完整玩法跑通、答疑 | 10min |
| HUD 搭建 | hud.tscn 独立场景、CanvasLayer 分层、锚点定位、信号绑定、**StyleBox 亮色 UI** | 35min |
| 标题界面 | 半透明遮罩、开始按钮、限步勾选；**开始后才生成棋盘** | 15min |
| 素材与音频 | 宝石贴图替换、音效（现成 ogg）、BGM 循环 | 20min |
| 胜负判定 | 限步可选结算、游戏结束界面 | 10min |
| 导出发布 | export_presets 打包 Windows exe / Web，测试运行 | 15min |
| 结课 + Gamejam 预告 | 课程总结、进阶方向、后续活动 + **官方教程自学指路** | 10min |

**本课知识点：**
- **官方 HUD 架构（对齐 Dodge the Creeps）**：独立 `hud.tscn` + `hud.gd`，`start_game` 信号；Main 持有 `$Music` / `$SfxClick/Select/Swap/Clear`——不要中间层 ui.gd（已删）
- **CanvasLayer**：UI 独立成层，不被游戏内容遮挡（官方 HUD 标准做法）
- **锚点 Anchor Presets**：定位 UI 控件（分数居中顶部、按钮居中等）
- **StyleBox 亮色 UI（v2.1）**：默认灰按钮在深石板灰蓝背景 `(0.12, 0.14, 0.18)` 下对比不足——主按钮用亮黄、次要用亮蓝，**深色字**；StyleBox 是资源不是代码，改 tscn 即可（M5 已验证的对比度教训）
- 信号（signal）机制：UI 与游戏逻辑解耦
- **标题半遮罩 + 延后生成棋盘**：标题界面不暴露盘面（board `_ready` 只算 origin 不 fill_grid），`new_game → reset_game → fill_grid`；回标题 `clear_board()`——教学点：节点/资源生命周期
- **音效：直接加载现成 ogg**（Kenney UI Sounds：click/tap/switch），不用程序化生成
- **BGM**：`$Music` 循环播放（现行：House In a Forest Loop.ogg），音量别盖过音效
- 导出：`export_presets.cfg` 已配——Windows Desktop → build/GodotMatch3.exe；Web 关 thread_support
- 胜负：限步可选；步数用尽即结束（当前动画结束后进结算）

**演示代码：** `hud.tscn` + `hud.gd`（信号绑定）+ `main.gd`（new_game / 音频）+ 导出配置

**课后作业：** 把作业成品发给讲师 / 想一个进阶玩法（特殊宝石、关卡）

**常见坑：** 新加 .ogg 无 .import 时 `preload` 报错（需 `godot --path <项目> --headless --import`）；导出后字体/图标丢失（嵌入字体）；信号连接后忘记断开（场景重载报错）；Web 导出要关 thread_support
