## A3 · 标题界面幕后：幕布 + 延后生成棋盘 ⭐

**标题：** 为什么标题界面是"空"的？——幕布 + 延后生成

**页面内容（对比 + 说明）：**

```
【幕布】Mask 半透明盖住全屏：画面干净，注意力在按钮上
        （而且棋盘本来就空的——幕布其实"防了个寂寞" 😄）

【延后生成】如果 board 一进场景就 fill_grid：
  标题界面下玩家已经看见整盘宝石 → 露馅 + 每局都是同一盘
v3.2 做法：
  board._ready      → 只算 origin（棋盘位置），不生成宝石
  new_game（点开始）→ reset_game → fill_grid（这时才生成）
  get_gem_at        → 空盘直接返回 null（点空白 = 取消选中）
```

**人话（复习 L1 生命周期）：**
- **节点生命周期**：`_ready`（进场景）≠ `new_game`（点开始）——**两件事分开做**
- 标题阶段棋盘是**空壳**：位置算好，一颗宝石都没有
- 点「开始游戏」那一刻才生成——**每局都是新鲜的棋盘**

**讲师口播：**
「拼完壳回头看一眼：为什么标题界面是空的？两个原因。第一，**幕布**——Mask 半透明盖住全屏，画面干净；第二，**延后生成**——`_ready` 只算 origin，`new_game` 才 `fill_grid`。这是 **L1 生命周期知识的实战应用：节点的 `_ready` 进场景就触发，按钮的 `new_game` 玩家点击才触发——不是一回事。** 把"准备"和"开始"拆开，标题界面就不露盘。」

**验证点：** 现场删掉 `new_game` 里的 `board.reset_game()` → F5 点开始，棋盘不出现（验证"生成发生在 reset_game"）。

## B1 · hud.gd ① 信号 + 节点引用 + 按钮回调（喇叭）⭐

**标题：** hud.gd：两个"喇叭" + 两个遥控器 + 两个按钮

**页面内容（代码，14 行）：**

```gdscript
extends CanvasLayer

## 对外信号：玩家点了「开始游戏」
signal start_game
## 对外信号：玩家点了「重新开始」
signal restart

## @onready：进场景树后取子节点（hud.tscn 里预置的控件）
@onready var score_label: Label = $ScoreLabel
@onready var restart_button: Button = $RestartButton

## 开始按钮被点 → 发 start_game 信号（Main 收到后开新局）
func _on_start_button_pressed() -> void:
	start_game.emit()

## 重新开始按钮被点 → 发 restart 信号（Main 收到后开新局）
func _on_restart_button_pressed() -> void:
	restart.emit()
```

**讲师口播：**
- **`signal start_game`** = 声明一个"喇叭"——hud 只会**喊**，不会做。具体谁去开新局，它不关心
- **`@onready var score_label: Label = $ScoreLabel`** = 拿 hud.tscn 里的控件引用——**`$ScoreLabel` 就是你们刚拼的那个节点！** L1 学的 @onready 套路
- **按钮回调** = 被点 → **喊一声** `start_game.emit()`。就这一件事——它不认识 main，也不知道 new_game 是什么
- 这两个回调就是 Part B 里要连的信号线目标（手册 Step 10：pressed → 这两个函数）

**验证点：** 提问：「`signal` 和 `func` 的区别？——signal 只声明"会有这件事发生"，func 是具体做什么。」

## B2 · hud.gd ② prepare_playing + update_score（藏 3 亮 2 + %d）

**标题：** hud.gd：界面切换 + 分数刷新

**页面内容（代码，10 行）：**

```gdscript
## 进入对局：隐藏标题界面，显示分数与重开按钮
func prepare_playing() -> void:
	$Mask.hide()             # 隐藏半透明遮罩（标题画面的"幕布"）
	$Message.hide()          # 隐藏标题文字
	$StartButton.hide()      # 隐藏开始按钮
	restart_button.show()    # 显示重新开始按钮
	score_label.show()       # 显示分数

## 刷新分数显示：分数 Label 的文字
func update_score(score: int) -> void:
	score_label.text = "分数: %d" % score    # %d 是占位符，被 score 替换
```

**讲师口播：**
- **`prepare_playing()`** = 界面"换台"：**藏 3 个（遮罩/标题/开始按钮），亮 2 个（分数/重开按钮）**——就是 A1 图纸里那两组！**界面切换的本质就是显隐组合**，`$Mask.hide()` 藏的正是你亲手拼的 Mask
- **`"分数: %d" % score`** = **`%d` 是占位符**，被后面的数字替换。`"分数: %d" % 30` = `分数: 30`——**格式化字符串**，以后写 UI 天天用
- 这个函数就是 board `score_changed` 信号的"接听方"——B3 接线时正式登场

**验证点：** 现场改：`"分数: %d" % score` → `"当前分数 %d 分!" % score`，F5 看效果。

## B3 · main.gd 新增①：hud 声明 + _ready 接线 ⭐

**标题：** main.gd 新增（一）：声明 + 接线现场

**页面内容（代码，9 行）：**

```gdscript
## 新声明：拿到 HUD 界面层（加在 board 声明下面）
@onready var hud: CanvasLayer = $HUD

func _ready() -> void:
	## 信号连接（观察者模式）：HUD/Board 发信号 → 这里接住执行
	hud.start_game.connect(new_game)               # 点「开始」→ 开新局

```

## B5 · main.gd 新增③：消除音效 + BGM 循环

**标题：** main.gd 新增（三）：两个小函数

**页面内容（代码，6 行）：**

```gdscript
## 每次开始消除 → 播消除音效（B3 第四条线的接听方）
func _on_match_cleared() -> void:

## BGM 设为无缝循环（is/as = 类型判断和转换）

## B6 · 为什么这么绕？解耦 = 好改

**标题：** 为什么不直接 hud → board？——解耦

**页面内容（对照）：**

```
【直接调用（耦合）】              【信号（解耦）】
hud 里写：                        hud 喊一声 start_game
  board.reset_game()                └ main 接住 → 指挥 board

  ...                            hud 完全不认识 board

**讲师口播：**

## C3 · 总结②：四条信号线：只喊一声，不指挥 ⭐

**标题：** 总结：四条信号线——整台机器怎么协作

**页面内容（信号流图）：**

```
hud.start_game ──────→ main.new_game ──────→ board.reset_game
  （点开始）              （开新局）              （重建棋盘）

hud.restart ──────────→ main.new_game
  （点重开）              （直接开新局，不回标题）

board.score_changed ──→ hud.update_score
  （分数变了）              （刷新显示——B2 那个函数！）

board.match_cleared ──→ main 播消除音效
  （开始消除）              （$SfxClear.play）
```

**人话（观察者模式）：**
- **发信号的不认识收信号的**：hud 喊"开始！"——它不知道也不关心谁去开新局
- **收信号的不关心谁发的**：main 接住"分数变了"就刷新——不管谁改的分数
- 好处：**改一边不碰另一边**——换 HUD 样式不用动 board，加新模式不用动 hud

**讲师口播：**
「四条线，全在 main 的 `_ready` 里接好——B3 你们看过接线现场，现在从全景再看一遍：hud→main 两条（开始/重开）、board→hud 一条（分数——就是 B2 里 `update_score` 那个函数）、board→main 一条（音效）。**hud 完全不认识 board**——它只对 main 喊。这就是**观察者模式**：喊话的人不关心谁听，听话的人不关心谁喊。整个游戏就靠这四条线转起来。」

**验证点：** 提问：「第三条线的接听方是谁？——`hud.update_score`，B2 里你亲手改过的那行 `%d`。」

## C4 · 总结③：两种协作方式：打电话 vs 广播

**标题：** 总结：两种协作方式——打电话 vs 广播

**页面内容（左右双栏对照 + 中间蓝箭头）：**

```
【函数调用 = 打电话】           【信号 = 广播】
  点名找谁：                       喊一声，谁听谁接：
  main._do_swap()                  hud.start_game.emit()
  → board.try_swap()               → main 在 _ready 里 connect
  （调用方知道被调方存在）           （双方互不认识也能协作）

  L1-L3 全是这种方式                L4 今天新学：观察者模式
  适合：明确的分工链                适合：UI ↔ 逻辑解耦
```

**讲师口播：**
「最后一句总结：整个项目其实只有两种协作方式。前三课我们写的都是**函数调用**——就像**打电话**：你得知道对方号码（函数名），点名找谁。今天学的**信号**是另一种——**广播**：喊一嗓子，不点名，谁听了谁接。打电话要求**双方认识**；广播允许**互不相识**。四节课你学的所有东西，拆到底就是这两件事：**怎么把一件事拆开（L1-L3），以及怎么让拆开的东西互相协作（L4）**。这一课，毕业了。」

**验证点：** 提问：「`hud.start_game.emit()` 之后，谁一定会执行？——不一定是 main！谁 connect 了就是谁。我们项目里是 main。」
