## 页面 2/6 · 架构全景图（四角色）

**标题：** 四个角色，各管一摊

**页面内容（架构图）：**

```
main.gd 指挥中心（106 行）
    │ 只管流程：开局 / 输入 / 状态机 / 指挥
    ▼ 调用（黑盒接口）
board.gd 规则权威（371 行）
    │ 生成 / 判定 / 交换 / 消除 / 下落
    ▼ 信号
gem.gd 棋子（58 行）    hud.gd 界面（28 行）
   表现：贴图/动画/面具   显示：分数/按钮
```

**人话：**
- **main** = 指挥中心：自己不干活，调别人（第 2 课的黑盒法！）
- **board** = 规则权威：一切规则它说了算（371 行，最多）
- **gem** = 棋子：只会表现（换图、动画、面具亮灭）
- **hud** = 界面：只负责显示和"喊一声"

**代码地图标签：** 📍 架构全景

**讲师口播：**
「四个角色：main 是**指挥中心**——四节课我们精读的就是它；board 是**规则权威**——371 行最多，但你们用黑盒法只认识 5 个接口；gem 是**棋子**——58 行，表现层；hud 是**界面**——28 行，最少。**代码行数就是分工的体现：规则最复杂，界面最简单。**」

## 页面 3/6 · 信号流全景（观察者模式）

**标题：** 四条信号线：只喊一声，不指挥

**页面内容（信号流图）：**

```
hud.start_game ──────→ main.new_game ──────→ board.reset_game
  （点开始）              （开新局）              （重建棋盘）

hud.restart ──────────→ main.new_game
  （点重开）

board.score_changed ──→ hud.update_score
  （分数变了）              （刷新显示）

board.match_cleared ──→ main 播消除音效
  （开始消除）
```

**人话（观察者模式）：**
- **发信号的不认识收信号的**：hud 喊"开始！"——它不知道也不关心谁去开新局
- **收信号的不关心谁发的**：main 接住"分数变了"就刷新——不管谁改的分数
- 好处：**改一边不碰另一边**——换 HUD 样式不用动 board，加新模式不用动 hud

**代码地图标签：** 📍 main.gd → ③ 信号连接

**讲师口播：**
「四条线，全在 main 的 `_ready` 里接好。看第一条：点开始按钮 → hud 喊一声 `start_game` → main 接住执行 `new_game` → 指挥 board `reset_game` 重建棋盘。**注意：hud 完全不认识 board**——它只对 main 喊。这就是观察者模式：**喊话的人不关心谁听，听话的人不关心谁喊**。好处？以后你换一套按钮皮肤，board 一行不用改。」

## 页面 4/6 · 实操 —— 改 HUD（改 tscn 不改代码）

**标题：** 实操：改按钮样式 + 游戏标题（不用写代码）

**页面内容：**
```
打开 scenes/hud.tscn
├─ 改按钮：选中 StartButton → 检查器 → StyleBox 资源
│    ├─ 换颜色（黄/蓝主题，两色按钮）
│    └─ 改 hover 效果
├─ 改标题：Message 节点 → text 改成你的游戏名
└─ 改分数显示：ScoreLabel → 字体大小/颜色

原理：界面样式是"资源"，不是代码——拖拖拽拽就改完
```

**讲师讲什么：**
- 为什么改 UI 不用写代码？——**样式是资源**（StyleBox），控件属性全在检查器面板
- 这就是架构解耦的好处：界面层随便改，逻辑层不受影响
- 完成标准：按钮变色、标题换成自己的名字、F5 正常运行

## 页面 5/6 · 导出 —— 打包成 exe / Web

**标题：** 打包：让游戏离开你的电脑

**页面内容（步骤 + 坑）：**
```
Windows exe：
  项目 → 导出 → Windows Desktop → 导出项目
  → 得到 .exe 文件，双击就能玩（别人不用装 Godot）

Web 版（可选）：
  导出选 Web，⚠️ 关闭 thread_support
  → 得到 .html + .wasm，可挂 itch.io / 静态托管

三个坑提前说：
  ① 首次导出前要装导出模板（版本要一致）
  ② 字体丢失 → 字体资源勾选"嵌入"
  ③ 新加的素材报错 → godot --headless --import
```

**讲师讲什么：**
- 打包 = 把工程变成"一个文件"——这是 L4 的交付：**发给别人玩**
- 三个坑提前踩：模板、字体、.import

## hud.tscn 节点结构（配合页 2 架构全景 + 实操页 4）

```
hud.tscn（CanvasLayer 界面层）
├── ScoreLabel   （Label）分数显示，左上角
├── RestartButton（Button）重新开始，右上角
├── Mask         （ColorRect）半透明遮罩 = 标题"幕布"
├── Message      （Label）标题文字
└── StartButton  （Button）开始游戏
```

**人话：** hud.tscn 就 5 个控件——3 个是标题界面用的（Mask/Message/StartButton），2 个是对局用的（ScoreLabel/RestartButton）。`prepare_playing()` 就是"藏 3 个亮 2 个"的切换。

## 调用链处理说明（对照全课原则）

- **信号是"喊一声"不是调用链**：`hud.start_game.emit()` 不直接调 main——它只是发广播，main 在 `_ready` 里 `connect` 接住。这是**观察者模式**（本课核心概念），和前三课的"函数调用"是两种协作方式，要对比着讲：函数 = 打电话（点名找谁），信号 = 广播（喊一声谁听谁接）
- **被调函数回顾**：`reset_game`（board ③，L1 见过）/ `try_swap`（L2 精讲）/ `resolve_board`（L3 精讲）——本课只标"📍 见 L1/L2/L3"，不重复展开，用信号流把它们串成全景
- **hud.gd 全貌**：28 行是四个文件里最短的——本课给全代码（块2/3），因为它是"界面层"唯一新内容
- **导出不是代码**：export_presets.cfg 是配置，实操环节操作编辑器界面，不写代码
