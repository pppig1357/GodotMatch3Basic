## 块1 · 架构四角色

```
┌─────────────────────────────────────────────────┐
│ main.gd（106 行）指挥中心                          │
│   只管流程：开局、输入、状态机、指挥 Board         │
│   持有：$Board / $HUD / $Music / $Sfx*            │
└──────────────┬──────────────────────────────────┘
               │ 调用（黑盒接口）
               ▼
┌─────────────────────────────────────────────────┐
│ board.gd（371 行）规则权威                         │
│   生成/判定/交换/消除/下落——一切规则              │
│   对外接口：reset_game / get_gem_at / try_swap    │
│             / resolve_board / world_to_grid       │
└──────────────┬──────────────────────────────────┘
               │ 信号（只喊一声，不指挥）
               ▼
┌────────────────────┐     ┌─────────────────────┐
│ gem.gd（58 行）棋子  │     │ hud.gd（28 行）界面   │
│   表现：贴图/动画/面具 │     │   显示：分数/按钮    │
└────────────────────┘     └─────────────────────┘
```

**信号流全景：**
```
hud.start_game ──→ main.new_game ──→ board.reset_game（开局）
board.score_changed ──→ hud.update_score（分数刷新）
board.match_cleared ──→ main 播消除音效
hud.restart ──→ main.new_game（重开）
```

**讲师讲什么：**
- 四角色各管一摊：**main 指挥、board 规则、gem 表现、hud 显示**
- 关键设计：**UI 与逻辑解耦**——hud 不直接叫 board 干活，只发信号"喊一声"，main 接住再指挥
- 观察者模式（信号）：发信号的不关心谁在听，收信号的不关心谁发的——两边互不认识也能协作

## 块2 · hud.gd 信号 + 节点引用（hud.gd ①）

```gdscript
extends CanvasLayer
## hud.gd —— 游戏「界面层」（HUD 脚本）
## 角色定位：只管"显示"——标题界面、分数、按钮。不碰任何游戏规则。
## 它通过信号通知 Main（观察者模式）：点按钮只是"喊一声"，具体干什么由 Main 决定。

## 对外信号：玩家点了「开始游戏」
signal start_game
## 对外信号：玩家点了「重新开始」
signal restart

## @onready：进场景树后取子节点（hud.tscn 里预置的控件）
@onready var score_label: Label = $ScoreLabel
@onready var restart_button: Button = $RestartButton
```

**讲师讲什么：**
- `signal` = 声明一个"喇叭"——hud 只会喊，不会做
- `@onready var ... = $节点名`：拿 hud.tscn 里的控件（L1 讲过 @onready 套路）

## 块3 · hud.gd 界面切换 + 分数刷新（hud.gd ②③④）

```gdscript
## 进入对局：隐藏标题界面，显示分数与重开按钮
func prepare_playing() -> void:
	$Mask.hide()             # 隐藏半透明遮罩（标题画面的"幕布"）
	$Message.hide()          # 隐藏标题文字
	$StartButton.hide()      # 隐藏开始按钮
	restart_button.show()    # 显示重新开始按钮
	score_label.show()       # 显示分数

## 刷新分数显示：分数 Label 的文字
func update_score(score: int) -> void:
	score_label.text = "分数: %d" % score    # %d 是占位符，被 score 替换

## 开始按钮被点 → 发 start_game 信号（Main 收到后开新局）
func _on_start_button_pressed() -> void:
	start_game.emit()

## 重新开始按钮被点 → 发 restart 信号（Main 收到后开新局）
func _on_restart_button_pressed() -> void:
	restart.emit()
```

**讲师讲什么：**
- `prepare_playing`：标题界面 → 对局界面（隐藏 3 个、显示 2 个）
- `update_score`：`"分数: %d" % score`——格式化字符串，%d 被数字替换
- 按钮处理 = **只喊一声**：`start_game.emit()`——hud 不知道也不关心谁去开新局

## 块4 · main.gd 信号连接（_ready）

```gdscript
func _ready() -> void:
	## 信号连接（观察者模式）：HUD/Board 发信号 → 这里接住执行
	## HUD 不直接认识 Main 的函数，只负责"喊一声"，实现界面与逻辑解耦
	hud.start_game.connect(new_game)               # 点「开始游戏」→ 开新局
	hud.restart.connect(new_game)                  # 点「重新开始」→ 也是开新局
	board.score_changed.connect(hud.update_score)  # Board 分数变化 → HUD 刷新显示
	board.match_cleared.connect(_on_match_cleared) # Board 开始消除 → 播放消除音效
	_setup_music_loop()                            # BGM 设为循环播放
	hud.update_score(board.score)                  # 初始显示分数 0
	$Music.play()                                  # 开始播 BGM
```

**讲师讲什么：**
- `信号.connect(函数)` = "听到喊声就执行这个函数"——**连接**是唯一的接线动作，全部在 _ready 一次接完
- 四条线看懂信号流：hud→main 两条（开始/重开）、board→hud 一条（分数）、board→main 一条（音效）
- **为什么这么绕？** 直接 `hud.button → board.reset_game` 不行吗？——行，但 hud 就"认识" board 了，两者耦合。以后换界面、加模式，牵一发动全身。**解耦 = 好改**

## 块5 · 导出发布要点

```
Windows exe：编辑器 → 项目 → 导出 → Windows Desktop → 导出项目
Web：        同上选 Web，⚠️ 关闭 thread_support（静态托管 / itch.io 用）

常见坑：
- 首次导出前装导出模板（编辑器 → 管理导出模板，版本要一致）
- 字体丢失 → 字体资源勾选"嵌入"（Export 时随包带走）
- 新素材无 .import → godot --path <项目> --headless --import
```

**讲师讲什么：**
- 打包 = 把"工程"变成"一个 exe 文件"——别人不用装 Godot 也能玩
- 导出模板 = 引擎的"打包工具"，首次要先下载
- 三个坑提前说：模板版本、字体嵌入、.import
