## 题目（讲师口述 + 白板）

**需求**：写一个函数，输入一组匹配（每组是 ≥3 个同色宝石的列表），输出这组匹配的总分。

**计分规则**：
- 每组 3 个 = **30 分**
- 每多 1 个 +10 分（4 连 = 40 分，5 连 = 50 分…）

**举例**：`[红红红, 蓝蓝蓝蓝]` → 30 + 40 = **70 分**

## 🔍 先看它怎么被调用（别急着写，先认识它的"雇主"）

> 难度设计：**先看调用点，再回来补全**——先理解这个函数将来干什么活，写起来就有方向

```gdscript
# clear_matches 里这样调用它（K1 页见过）：
var base: int = _calc_score(groups)   # 算基础分
var gained: int = base * chain        # × 连锁倍率
score += gained                       # 加进总分
```

**从调用点反推你要写的函数**：
- clear_matches 需要 `_calc_score` **返回一个总分 int**，拿来 `× chain` 再加进 `score`
- 所以你的函数：**吃进匹配组数组（groups），吐出总分（int）**
- 规则：每组 3 个 = 30 分，多 1 个 +10（模板注释里的提示已经帮你拆好步骤）

> 思路：函数先 `pass` 着没关系——先看懂它将来怎么被用（黑盒视角：调用方只关心"输入 groups、输出总分"），再回来写函数体

**❓ 为什么判断 `if n >= 3`？（输入不是已经保证 ≥3 了吗）**
- 现在的调用方 `find_match_groups` 确实保证每组 ≥3，但**好函数不赌调用方一定守约**
- 万一以后 M5 扩展（特殊宝石/新模式）有新的调用者，传了 <3 的组进来，`30 + (n - 3) * 10` 会算出**负分加成**（n=2 得 20 分）——`if n >= 3` 就是兜底：不够 3 个一律不算分
- 这叫**防御性编程**："约定"是调用方的事，"兜底"是函数的事（和 L2 的 `movers.is_empty()` 防御性返回同一个思想）

## 📎 讲师参考答案（学员写完后对照用，勿提前展示）

```gdscript
func _calc_score(groups: Array) -> int:
	var total := 0
	for group in groups:
		var n: int = group.size()
		if n >= 3:
			total += 30 + (n - 3) * 10
	return total
```

**验收要点**：
- `if n >= 3`（不是 `> 3`——3 个的组也要算）
- `(n - 3) * 10`（4 连 = 30+10=40）
- 有 `return total`
- 空数组循环不执行 → 返回 0
