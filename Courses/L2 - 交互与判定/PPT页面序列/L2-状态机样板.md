```
游戏现在空闲（IDLE）：
  点宝石     → 选中它（面具亮）          → 进入 SELECTED
游戏已选中一颗（SELECTED）：
  点自己     → 取消选中（面具灭）        → 回 IDLE
  点相邻宝石 → 交换两颗（核心玩法！）    → 进入交换流程
  点非相邻   → 换成选它（旧的面具灭新的亮）→ 保持 SELECTED
  点空白     → 取消选中                  → 回 IDLE
```

**状态切换表（模板 T1 —— 背下来就能改游戏）：**

| 当前状态 | 事件 | 下一个状态 |
|---------|------|-----------|
| IDLE | 点击宝石 | SELECTED |
| SELECTED | 点自己 / 点空白 | IDLE |
| SELECTED | 点相邻 | SWAPPING（交换中） |
| SELECTED | 点非相邻 | SELECTED（换选） |
| SWAPPING / RESOLVING | （任何点击） | 不变——**锁输入** |

**人话：** 规则先行，代码只是把这张表翻译成 `if`。**这张表背下来，今天的内容就学会一半了。**

## 页面 3/7 · 全貌页

**标题：** 状态机 + 点选交互 —— 完整代码（有了规则表，这页不吓人）

**页面内容①（状态枚举，一屏）：**

```gdscript
## 游戏状态机：任何时刻游戏都处于其中一个状态（同一时间只有一个）
## IDLE      = 空闲，等待玩家点击
## SELECTED  = 已选中一颗宝石，等待下一步（交换/取消/换选）
## SWAPPING  = 交换动画播放中 → 锁输入，防止连点出 bug
## RESOLVING = 消除/下落动画播放中 → 锁输入
enum State { IDLE, SELECTED, SWAPPING, RESOLVING }
```

**页面内容②（_on_pointer_down 完整代码）：**

```gdscript
func _on_pointer_down() -> void:
	var world := get_global_mouse_position()                     # 鼠标的屏幕坐标
	var clicked: Gem = board.get_gem_at(board.world_to_grid(world))  # 坐标换算→取那颗宝石
	if clicked == null:                                          # 点到空白（棋盘外）
		_deselect()
		state = State.IDLE
		return
	if state == State.SELECTED and selected != null:
		if clicked == selected:                                  # ① 点自己 → 取消选中
			_deselect()
			state = State.IDLE
			$SfxClick.play()
			return
		if board.is_adjacent(selected, clicked):                 # ② 点相邻 → 交换
			await _do_swap(selected, clicked)
			return
		_deselect()                                              # ③ 点非相邻 → 换成选它
		_select(clicked)
		$SfxSelect.play()
		return
	_select(clicked)                                             # 空闲状态点宝石 → 选中
	state = State.SELECTED
	$SfxSelect.play()
```

**页面内容③（对照提示）：** 跟规则表对号入座——`clicked == null` 就是"点空白"，`①` 就是"点自己"，`②` 就是"点相邻"，`③` 就是"点非相邻"，最后两行就是"IDLE 点宝石→选中"。**一模一样。**

**代码地图标签：** 📍 `main.gd` → ① 状态枚举 + ⑥ 点选交互

**讲师口播：**
「现在看真实代码。是不是跟规则表长得一样？从上往下：先算鼠标点在哪格（这两行是块1 的坐标换算，等会儿实操细讲），然后五个分支对应五行规则。**先背表再看代码，就不会被 if 嵌套吓到。**先记住主干，下一页我们挑重点拆。」

## 页面 4/7 · 分段精讲① —— 状态锁 + 点空白

**标题：** 两个"保险丝"：动画期间锁输入 + 点空白取消

**页面内容①（_unhandled_input —— 输入入口 + 状态锁）：**

```gdscript
func _unhandled_input(event: InputEvent) -> void:
	# 动画播放中（SWAPPING/RESOLVING）直接忽略输入——状态锁，防止连点
	if state == State.SWAPPING or state == State.RESOLVING:
		return
	if event.is_action_pressed("click"):
		await _on_pointer_down()
```

**人话：** 所有鼠标点击都从这进来，但**动画播放中直接忽略**——不然你手速快连点两下，宝石还在飞就又要交换，游戏就乱了。`is_action_pressed("click")` 用的是 **InputMap 的"动作名"**（不是具体按键）——以后想改触摸/键盘，改配置就行，代码不用动（块1 详讲）。

**页面内容②（点空白分支）：**

```gdscript
	if clicked == null:                                          # 点到空白（棋盘外）
		_deselect()
		state = State.IDLE
		return
```

**人话：** 点棋盘外面？当作"我不想选了"——熄灭面具、回到空闲。**所有分支都保证一件事：画面（面具亮灭）和数据（state/selected）同步**。

**板书：** 画时间轴：点击 → 锁检查 → 换坐标 → 分支判断

**代码地图标签：** 📍 `main.gd` → ⑤ 输入 + ⑥ 点选交互 · 分支 0/4

**讲师口播：**
「两个保险丝。第一个：**动画期间锁输入**——SWAPPING 和 RESOLVING 这两个状态，任何点击直接无视。为什么要锁？想想：宝石交换动画 0.15 秒，你在这 0.15 秒里又点了一下，会发生什么？对，宝石还没落位就又要动，直接穿帮。**状态锁 = 游戏的刹车。**第二个：点空白 = 取消选中——这是规则表第一行之外的补充，保证任何时候你都能"反悔"。记住原则：**画面改了，数据也改，两边永远一致**。」

## 页面 5/7 · 分段精讲② —— 选中判定三分支（本课核心 ⭐）

**标题：** 选中了之后：点自己 / 点相邻 / 点非相邻

**页面内容（三分支代码高亮 + 流程图）：**

```gdscript
	if state == State.SELECTED and selected != null:
		if clicked == selected:                                  # ① 点自己 → 取消选中
			_deselect()
			state = State.IDLE
			$SfxClick.play()
			return
		if board.is_adjacent(selected, clicked):                 # ② 点相邻 → 交换（核心玩法）
			await _do_swap(selected, clicked)
			return
		_deselect()                                              # ③ 点非相邻 → 换成选它
		_select(clicked)
		$SfxSelect.play()
		return
```

**人话（三分支，对应规则表三行）：**
- **① 点自己**：啊，我不想要这颗了 → 灭面具、回 IDLE（点自己 = 反悔）
- **② 点相邻**：`board.is_adjacent(selected, clicked)` 问 Board「这两颗挨着吗？」——挨着就 `_do_swap` 交换（**核心玩法！**）。注意：**"相邻"的判断是 Board 说了算**（下面就是它的全部代码），Main 不自己算——黑盒法：规则的事问权威

```gdscript
## 相邻判断（board.gd ⑧）：曼哈顿距离 == 1（横差+纵差为 1）
func is_adjacent(a: Gem, b: Gem) -> bool:
	var dx := absi(a.grid_pos.x - b.grid_pos.x)
	var dy := absi(a.grid_pos.y - b.grid_pos.y)
	return dx + dy == 1
```

**人话：** 横差 + 纵差等于 1 = 上下左右相邻；斜对角是 2，不算。`absi` = 绝对值（Godot 4 用 `absi` 不是 `abs`，警告当错误会编不过）
- **③ 点非相邻**：远的那颗不要了，换选新点的这颗 → 旧面具灭、新面具亮，保持 SELECTED

**板书/动画：** 三分支流程图（点自己→取消 / 点相邻→交换 / 点非相邻→换选），每分支点击后浮现对应高亮段

**代码地图标签：** 📍 `main.gd` → ⑥ 点选交互 · 分支 1~3/4

**讲师口播：**
「这是今天的核心。选中一颗之后点其他地方，就三种可能：**点自己**——反悔了，取消；**点相邻**——这是重点，两颗交换，我们问 Board『挨着吗』，挨着就换；**点非相邻**——换选，旧面具灭新面具亮。大家注意 `is_adjacent` 这句——**判断相邻不是 Main 自己算的，是问 Board**。为什么？因为棋盘规则是 Board 的领域，Main 只管流程。这就是我们说的黑盒法：**用手机不用懂电路，调 Board 不用懂内部。**」

## 页面 6/7 · 调用链展开 —— 交换的黑盒 _do_swap（跨三文件）

**标题：** 拆开黑盒：点相邻之后，到底发生了什么？

**页面内容①（调用树 —— 先看骨架再看代码）：**

```
点相邻宝石
└─ _do_swap(a, b)              ← main.gd ⑧：只管流程
   ├─ 1. state = SWAPPING      ← 锁输入（刹车）
   ├─ 2. board.try_swap(a, b)  ← 问 Board：能换吗？（规则权威）
   │     ├─ 先交换数据 + 播放交换动画（board._animate_swap_pair）
   │     ├─ 检查有没有匹配（find_matches）
   │     ├─ 有匹配 → 返回 true
   │     └─ 没匹配 → 自动弹回原位 → 返回 false
   ├─ 3. 成功 → state = RESOLVING → await board.resolve_board()
   │        （消除 → 下落 → 连锁，第 3 课拆）
   └─ 4. 回 IDLE，等待下一次点击
```

**页面内容②（_do_swap 真实代码 —— 只有 10 行）：**

```gdscript
func _do_swap(a: Gem, b: Gem) -> void:
	state = State.SWAPPING          # 1. 锁输入
	_deselect()                     #    熄灭面具（交换开始就不算选中了）
	$SfxSwap.play()
	var ok: bool = await board.try_swap(a, b)   # 2. 问 Board（核心活包出去）
	if not ok:
		state = State.IDLE          #    没匹配 → 弹回，直接解锁
		return
	state = State.RESOLVING         # 3. 有匹配 → 锁住等结算
	await board.resolve_board()     #    消除/下落/连锁（第 3 课）
	state = State.IDLE              # 4. 一切结束，解锁
```

**人话：** `_do_swap` 自己**一行规则都没写**——它只做四件事：锁状态、问 Board、等结算、解锁。**交换成不成功、弹不弹回，全是 Board 的 try_swap 内部的事**（黑盒：这页只看接口 `try_swap(a, b) -> bool` 的用法，内部实现块5 讲）。

**代码地图标签：** 📍 `main.gd` → ⑧ 交换流程 + `board.gd` → ⑧ 交换（对外接口③）

**讲师口播：**
「这就是"点相邻"之后的全过程——看这棵调用树：Main 锁上状态（SWAPPING），然后**把活包给 Board 的 try_swap**。Board 先让两颗宝石飞过去（动画），再检查有没有凑成三消：有就成，没有就弹回原位。Main 拿到结果：成功就继续锁着等结算，失败就解锁。注意 `_do_swap` 十行代码里**没有任何规则**——规则全在 Board 里。这就是分工：**Main 管流程，Board 管规则。**」

## 调用链处理说明（对照全课原则）

- **跨文件调用**：`_do_swap → board.try_swap` 是跨 main/board 两文件——本页给完整调用树 + 接口用法（`try_swap(a, b) -> bool`），**内部实现不展开**（黑盒法：L2 只要求认识接口；try_swap 内部是块5 内容）
- **被调函数不黑盒原则的边界**：`try_swap` 是**官方定义的黑盒**（board 五大对外接口之一），所以这里不展开；但 `_select/_deselect`（简单、同文件）直接给代码：
  - `_select(gem)`：记录 + `gem.set_selected(true)`（面具亮）
  - `_deselect()`：`gem.set_selected(false)` + 清空记录（面具灭）
  - （这两行在逐行讲稿里带过，不占页面）
- **伏笔**：`resolve_board`（消除/下落/连锁）→ 第 3 课拆；`try_swap` 内部的 `find_matches` → 本课块4 精讲
