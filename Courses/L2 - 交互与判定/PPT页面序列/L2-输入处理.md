## 页面 2/6 · 概念页 —— InputMap「动作」（为什么不用"按键"）

**标题：** 用"动作"不用"按键"（官方推荐写法）

**页面内容（代码 + 对照表）：**

```gdscript
func _unhandled_input(event: InputEvent) -> void:
	if state == State.SWAPPING or state == State.RESOLVING:
		return                    # 状态锁（状态机样板讲，先不管）
	if event.is_action_pressed("click"):    # ← 看这一行
		await _on_pointer_down()
```

**对照表：**

| 写法 | 含义 | 问题 |
|------|------|------|
| `event.is_action_pressed("click")` | 按下了名为 click 的**动作** | 无——动作可在 InputMap 里任意绑定按键 |
| `event is InputEventMouseButton and event.button_index == MOUSE_BUTTON_LEFT` | 按下了**鼠标左键** | 写死按键：以后想支持触摸/键盘/手柄，代码全要改 |

**人话：** `click` 是 InputMap 里配好的"动作名"（默认绑鼠标左键）——**代码只认动作名，不认具体按键**。想改成触摸？改配置就行，代码一行不动。就像你家门牌号是"302"，别人问你住哪你说"302"而不是"左边数第 7 扇门"。

**代码地图标签：** 📍 `main.gd` → ⑤ 输入

**讲师口播：**
「看这一行：`is_action_pressed("click")`。`click` 不是按键，是**动作**——在项目设置 InputMap 里配好的名字，默认绑鼠标左键。为什么绕一圈？**因为代码只认动作名，以后想加触摸、加键盘，改配置不改代码。** 这就是官方推荐的写法，别学网上那些直接判断鼠标左键的——那是给自己埋坑。」

## 页面 3/6 · 结构图页 —— 点击 → 坐标 → 取宝石（"伪代码"）

**标题：** 一次点击的完整旅程（先看流程再看代码）

**页面内容（流程图）：**

```
鼠标点下去
│
├─ 1. 拿到屏幕坐标        get_global_mouse_position()   → (320, 240)
├─ 2. 翻译成网格坐标      board.world_to_grid(世界坐标)  → (col=3, row=4)
```

**人话：** 点一下 = **坐标 → 格子 → 宝石 → 规则** 四步。第 2、3 步都是问 Board（黑盒接口：`world_to_grid` 翻译坐标、`get_gem_at` 取宝石）——Main 自己不算坐标、不查棋盘，**只负责流程**。

**代码地图标签：** 📍 流程图 ↔ `main.gd` ⑥ 开头 + `board.gd` ④

**讲师口播：**
「一次点击，游戏内部走四步：**拿坐标 → 翻成格子 → 取宝石 → 判规则**。注意第 2、3 步——Main 不自己算，是问 Board：『world_to_grid，这个坐标是第几格？』『get_gem_at，这格是谁？』。这就是黑盒法：**Main 是个指挥，干活的都是 Board。** 记下这个流程图，实操时你们要亲手打印这个坐标。」

## 页面 4/6 · 全貌页 —— world_to_grid 真实代码

**标题：** world_to_grid —— 屏幕坐标 → 网格坐标（翻译官）

**页面内容（代码）：**

```gdscript
## 世界坐标 → 网格坐标：像素位置落在第几格；点在棋盘外返回 (-1,-1)
func world_to_grid(world: Vector2) -> Vector2i:
	var local := world - origin              # 相对棋盘左上角的偏移
	var col := int(floor(local.x / CELL_SIZE))
	var row := int(floor(local.y / CELL_SIZE))
	if col < 0 or col >= GRID_SIZE or row < 0 or row >= GRID_SIZE:
		return Vector2i(-1, -1)              # 越界标记
	return Vector2i(col, row)
```

**人话（三行核心）：**
- `local = world - origin`：先减去棋盘左上角位置——把"屏幕坐标"变成"相对棋盘的位置"（origin 是 L1 讲过的棋盘居中偏移）
- `col = floor(local.x / 64)`：**除以格宽 64，向下取整**——坐标 320 → 320/64 = 5 → 第 5 列（一格 64 像素，除一下就知道落在第几格）
- 越界检查：算出负数或 ≥8 → 说明点棋盘外了 → 返回 `(-1,-1)` 这个**特殊标记**（状态机里 `get_gem_at` 拿到 (-1,-1) 会返回 null → 触发"点空白取消"分支）

**代码地图标签：** 📍 `board.gd` → ④ 坐标换算

**讲师口播：**
「这是翻译官本人。核心就一行：**除以 64**。一格 64 像素，你的鼠标横坐标 320，除以 64 等于 5——第 5 列。为什么用 floor？因为点在第 4.7 格也是第 4 格，向下取整。**除法和取整，就是像素到格子的秘密。** 最后那个 `(-1,-1)` 是暗号：点棋盘外了，后面用这个暗号触发『点空白取消』。」

## 页面 5/6 · 全貌页 —— get_gem_at + 组合拳

**标题：** get_gem_at —— 从格子到宝石（加上 world_to_grid 就是完整一行）

**页面内容（代码）：**

```gdscript
## 取指定格的宝石；越界、空盘或空位都返回 null
func get_gem_at(pos: Vector2i) -> Gem:
	if grid.is_empty():
		return null
	if pos.x < 0 or pos.x >= GRID_SIZE or pos.y < 0 or pos.y >= GRID_SIZE:
		return null
	return grid[pos.x][pos.y] as Gem
```

**页面内容②（组合拳 —— 状态机里的完整一行）：**

```gdscript
	var clicked: Gem = board.get_gem_at(board.world_to_grid(world))
```

**人话：** 从里往外读：`world_to_grid(world)` 先翻译坐标 → 结果直接塞给 `get_gem_at` 取宝石 → 拿到 `clicked`（一颗宝石或 null）。**一行代码干了两步**——这就是"函数套函数"：里面的先算，结果给外面用。

**代码地图标签：** 📍 `board.gd` → ④ 坐标换算 + `main.gd` → ⑥ 点选交互

**讲师口播：**
「`get_gem_at` 更简单：拿着格子坐标，去 `grid` 数组里把宝石掏出来；越界、空位就返回 null。然后把两个函数套一起——`get_gem_at(world_to_grid(world))`，从里往外读：先翻译成格子，再取宝石。**一行搞定四步旅程的后两步。** 这句在状态机样板里见过吧？当时没细讲，现在懂了。」
