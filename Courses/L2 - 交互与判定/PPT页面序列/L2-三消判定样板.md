## 页面 2/7 · 伪代码骨架页 ⭐（先看思想，再看代码）

**标题：** 先看思想：怎么"找"三消？（不碰代码版）

**页面内容（伪代码 + 图示）：**

```
找出所有匹配组（一组 = 一段连续 ≥3 个同色宝石）
│
├─ 1. 横向：一行一行扫（8 行）
│     对每一行：
│       ① 找到一段「连续同色段」（叫 run）——从某格开始向右延伸
│       ② 颜色变了 / 到头了 → 这段结束
│       ③ 长度 ≥ 3 → 收进结果（一组）
│       ④ 从这段之后继续找下一段
│
├─ 2. 纵向：一列一列扫（8 列，逻辑一模一样，只是方向换一下）
│
└─ 3. 返回所有组
```

**配图（核心图示 —— 一行格子的 run 动画）：**

```
[红][红][红][蓝][红]     ← 从第 0 格开始，红色 run 延伸
   ↑start        ↑颜色变了，停！
   长度 = 3 ≥ 3 → 收下这一组
   然后从蓝色那格继续找下一段……
```

**人话：** 就像玩找茬——**逐行逐列找"连续同色段"**，够 3 个就记下来。扫完所有行 + 所有列，棋盘上所有三消就全找到了。**整个算法就一句话：找 run，够长就收。**

**代码地图标签：** 📍 伪代码 ↔ `board.gd` → ⑥ 匹配判定

**讲师口播：**
「先别看代码，看这个思想。核心概念叫 **run**——就是一串连续同色的宝石。算法做的事：**逐行找 run、逐列找 run，长度 ≥3 就收进结果**。注意细节：从 run 的**后面**继续找，不能漏；空位直接跳过。这个思想值 20 分钟——下一页看代码，你会发现代码就是这段话的直译。」

## 页面 3/7 · 全貌页

**标题：** find_match_groups —— 完整代码（跟伪代码对号入座）

**页面内容①（横向扫描 —— 高亮前半段）：**

```gdscript
func find_match_groups() -> Array:
	var groups: Array = []
	# —— 横向（逐行扫）——
	for row in range(GRID_SIZE):
		var run_start := 0
		while run_start < GRID_SIZE:
			var gem0: Gem = grid[run_start][row] as Gem
			if gem0 == null:                # 空位跳过
				run_start += 1
				continue
			var run_type: int = gem0.type   # 这段连续段的颜色
			var run_end := run_start + 1
			while run_end < GRID_SIZE:      # 向右延伸，直到颜色不同或越界
				var g: Gem = grid[run_end][row] as Gem
				if g == null or g.type != run_type:
					break
				run_end += 1
			if run_end - run_start >= 3:    # 连续 ≥3 才算一组
				var group: Array = []
				for c in range(run_start, run_end):
					group.append(grid[c][row])
				groups.append(group)
			run_start = run_end             # 从这段之后继续找下一段
```

**页面内容②（对照提示）：** 伪代码的 ①②③④ 四步 = 代码里的 `run_start`（起点）/ `run_end`（终点）/ `while` 延伸 / `>= 3` 判断——**一行对一步**。

**底部提示：** 纵向扫描代码完全一样，只是把 `grid[列][行]` 的下标换过来——一页放不下，PPT 备注里贴完整版

**代码地图标签：** 📍 `board.gd` → ⑥ 匹配判定

**讲师口播：**
「看，代码就是伪代码的直译：`run_start` 是这段的起点，`run_end` 是终点，里面的 `while` 就是"向右延伸"，`run_end - run_start >= 3` 就是"够长就收"。**先有思想再看代码，这 20 行就不吓人了。**纵向扫描不用看——逻辑一模一样，只是把行换成列。」

## 页面 4/7 · 分段精讲 —— run 的诞生与延伸（本页唯一要"懂"的细节 ⭐）

**标题：** 拆一个 run：起点 → 延伸 → 判定 → 收组

**页面内容（用一行格子逐步演示，配代码片段）：**

```
第 3 行：  [蓝][蓝][蓝][黄][蓝][蓝][蓝][蓝]
             ↑run_start=0，颜色=蓝
             延伸：0→1 蓝 ✓，1→2 蓝 ✓，2→3 黄 ✗ 停！
             run = [0,1,2]，长度 3 ≥ 3 → 收下（一组 3 颗）
             下一段从 run_end=3 开始：黄色 run，长度 1 < 3 → 不收
             再下一段从 4 开始：蓝色 run，长度 4 ≥ 3 → 又收一组！
```

**对应代码（高亮）：**

```gdscript
			var run_start := 0            # ① 起点：从这格开始
			...
			var run_end := run_start + 1
			while run_end < GRID_SIZE:    # ② 延伸：颜色相同就一直向右
				var g: Gem = grid[run_end][row] as Gem
				if g == null or g.type != run_type:
					break                 #    颜色不同/空位 → 停
				run_end += 1
			if run_end - run_start >= 3:  # ③ 判定：够 3 个才收
				...
			run_start = run_end           # ④ 下一段：从这段后面继续
```

**人话（四个变量一台戏）：**
- `run_start` = 这段从哪开始；`run_end` = 延伸到哪（不含）
- 延伸条件 = **颜色相同且不是空位**；颜色一变就 break
- `run_end - run_start` = 这段长度；**≥3 才收组**
- 收完一组，**起点直接跳到 run_end**——不回头，保证每格只被扫一次（效率！）

**板书/动画：** 一行格子逐格点亮动画（蓝蓝蓝 → 黄 → 蓝蓝蓝蓝，run 分段变色）

**代码地图标签：** 📍 `board.gd` → ⑥ 匹配判定 · 横向扫描

**讲师口播：**
「整个算法唯一要真正搞懂的，就是**一个 run 怎么被找出来**。看这行格子：起点是 0，蓝色。延伸——1 也是蓝，2 也是蓝，到 3 是黄，停。这段长度 3，收下。**然后注意：起点直接跳到 3**，从黄格开始找下一段——黄的 run 只有 1 个，不收；再往后是 4 颗蓝，长度 4，又收一组。这个『起点跳到 run_end 不回头』的设计，保证每颗宝石只被检查一次——**又快又不漏**。」

## 页面 5/7 · 去重 —— 一颗宝石不能算两次（L 形陷阱）

**标题：** 纵向扫描 + 去重：L 形三消怎么办？

**页面内容①（L 形配图 + 解释）：**

```
横向找到一组：       纵向也找到一组：
[红][红][红]          [红]
                      [红]      ← 中间这颗红，横组里有它，竖组里也有它！
                      [红]

如果直接两组都算 → 中间那颗被消除两次 → 计分翻倍 bug！
```

**页面内容②（find_matches + _add_unique 真实代码）：**

```gdscript
## 把匹配组"摊平"成一个宝石数组（一颗宝石可能同时属于横/纵两组，需去重）
func find_matches() -> Array:
	var matched: Array = []
	var groups := find_match_groups()
	for group in groups:
		for gem in group:
			_add_unique(matched, gem as Gem)
	return matched

## 朴素去重：gem 不在数组里才追加（避免同一颗被横纵两组重复计算）
func _add_unique(arr: Array, gem: Gem) -> void:
	if gem == null:
		return
	if arr.has(gem):
		return
	arr.append(gem)
```

**人话：** 横扫发现 L 的横臂、纵扫发现 L 的竖臂，**中间那颗被找到两次**——`_add_unique` 检查"已经收过了吗？收过就跳过"，保证每颗宝石在结果里**只出现一次**。

**代码地图标签：** 📍 `board.gd` → ⑥ 匹配判定 · find_matches

**讲师口播：**
「纵向扫描代码和横向一模一样，不看了。但有个陷阱必须讲——**L 形三消**：横着看有一组，竖着看也有一组，中间那颗被找到两次。如果直接算，它会**被消除两次、计分翻倍**，游戏就穿帮了。所以 `find_matches` 做一步去重：收过的宝石不重复收。**这就是 `_add_unique` 的存在意义**——一颗宝石，只算一次。」

## 页面 6/7 · 调用链展开 —— 判定被谁用？（try_swap 的检查）

**标题：** 这个"检查器"在哪里被调用？

**页面内容①（调用树）：**

```
点相邻 → _do_swap → board.try_swap(a, b)          ← 状态机样板讲过
│
├─ ① 数据交换 + 播放动画
├─ ② find_matches()   ← 就是今天学的判定！
│      ├─ 有匹配 → 交换成立（返回 true）→ 进入结算（第 3 课）
│      └─ 没匹配 → 数据换回去 + 动画弹回（返回 false）
```

**页面内容②（try_swap 真实代码 —— 判定在中间）：**

```gdscript
func try_swap(a: Gem, b: Gem) -> bool:
	if a == null or b == null:
		return false
	if not is_adjacent(a, b):
		return false
	_swap_grid_data(a, b)              # ① 数据交换
	await _animate_swap_pair(a, b)     # ② 播放交换动画
	var matches := find_matches()      # ③ 检查交换后有没有匹配 ← 今天学的
	if matches.is_empty():
		_swap_grid_data(a, b)          # ④ 没有 → 换回去（弹回）
		await _animate_swap_pair(a, b)
		return false
	return true                        # ⑤ 有匹配 → 交换成立
```

**人话：** 判定是个**检查器**——交换后问它"成了吗"，成了留下、没成弹回。**为什么交换成立要"先换再查"？** 因为匹配只有交换后才可能产生——这就是"试错"思想：**先做，再检查，不行就回滚**（下节课的连锁也是这个思路）。

**页面内容③（内部函数展开 —— 不黑盒，数据与表现分离）：**

```gdscript
## ① 只换"数据"：grid 数组 + 各自的 grid_pos（不碰屏幕）
func _swap_grid_data(a: Gem, b: Gem) -> void:
	var pos_a := a.grid_pos
	var pos_b := b.grid_pos
	grid[pos_a.x][pos_a.y] = b
	grid[pos_b.x][pos_b.y] = a
	a.grid_pos = pos_b
	b.grid_pos = pos_a

## ② 交换动画：并行滑到新位置（Tween，📍 第 3 课 T3 模板——今天只知"会等动画播完"）
func _animate_swap_pair(a: Gem, b: Gem) -> void:
	var tween := create_tween()
	tween.set_parallel(true)
	tween.tween_property(a, "position", grid_to_world(a.grid_pos), 0.15)
	tween.tween_property(b, "position", grid_to_world(b.grid_pos), 0.15)
	await tween.finished
```

**人话：** ①先换"数据"（grid 表和记录的位置），②再播"动画"（屏幕移动）——**数据与表现分离**：弹回时也是先换数据再播动画。动画细节今天不深挖（第 3 课 T3 模板），但代码先看着眼熟。

**代码地图标签：** 📍 `board.gd` → ⑧ 交换（try_swap）+ ⑥ 匹配判定

**讲师口播：**
「今天学的判定，用在哪？看 try_swap——交换动画播完，立刻调 `find_matches()` 检查：**有匹配，交换成立；没匹配，数据换回去、宝石弹回原位**。这就是为什么你们交换失败时宝石会弹回来——不是 bug，是 `try_swap` 的回滚。记住这个套路：**先做 → 检查 → 不行就回滚**，这是游戏开发最常用的思想之一，第 3 课的连锁也是它。」
