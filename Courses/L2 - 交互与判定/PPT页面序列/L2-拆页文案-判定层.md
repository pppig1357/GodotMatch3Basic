## J2 · board.gd 零件①：find_match_groups 横向扫描 ⭐

**标题：** 拆一个 run：四个变量一台戏（关键行）

**页面内容（关键行摘录 19 行，超 15 行铁律的讲解特例 —— ⚠️ 不要直接粘贴：收组省略会语法报错！完整代码见附件 `L2-完整代码.txt`）→ 📌 归属：board.gd（L1 已有，追加）：**

```gdscript
func find_match_groups() -> Array:
	var groups: Array = []
	for row in range(GRID_SIZE):
		var run_start := 0
		while run_start < GRID_SIZE:
			var gem0: Gem = grid[run_start][row] as Gem
			if gem0 == null:
				run_start += 1
				continue
			var run_type: int = gem0.type
			var run_end := run_start + 1
			while run_end < GRID_SIZE:
				var g: Gem = grid[run_end][row] as Gem
				if g == null or g.type != run_type:
					break
				run_end += 1
			if run_end - run_start >= 3:
				pass  # 收组见附件（完整版 L2-完整代码.txt）
			run_start = run_end
```

**配图（run 逐步演示）：**

```
第 3 行：  [蓝][蓝][蓝][黄][蓝][蓝][蓝][蓝]
             ↑run_start=0，颜色=蓝
             延伸：0→1 蓝 ✓，1→2 蓝 ✓，2→3 黄 ✗ 停！
             run = [0,1,2]，长度 3 ≥ 3 → 收下（一组 3 颗）
             下一段从 run_end=3 开始：黄色 run 长度 1 < 3 → 不收
             再下一段从 4 开始：蓝色 run 长度 4 ≥ 3 → 又收一组！
```

**讲师口播（本页是"唯一要懂"的细节）：**
- **四个变量一台戏**：`run_start`（起点）/ `run_end`（终点，不含）/ `run_type`（颜色）/ 长度 = `run_end - run_start`
- 伪代码 ①②③④ 四步 = 代码结构——**一行对一步**（口播指着代码讲对应关系）
- **起点跳到 run_end 不回头** = 每格只被扫一次（效率 + 不漏）
- ⚠️ 完整 45 行代码在**附件 txt** 里——页面上只放关键行（收组几行省略了，讲师打开附件逐行带过）

## J4 · board.gd 零件③：_add_unique（L 形去重）

**标题：** 去重：一颗宝石不能算两次（L 形陷阱）

**页面内容①（L 形配图，无代码）：**

```
横向找到一组：       纵向也找到一组：
[红][红][红]          [红]
                      [红]      ← 中间这颗红，横组里有它，竖组里也有它！
                      [红]

如果直接两组都算 → 中间那颗被消除两次 → 计分翻倍 bug！
```

**代码块（⚠️ L1 已写过 `_add_unique`，本页不重复写——只讲解。想换成这个三段式版本，先删旧的再粘贴）→ 📌 归属：board.gd：**

```gdscript
func _add_unique(arr: Array, gem: Gem) -> void:
	if gem == null:
		return
	if arr.has(gem):
		return
	arr.append(gem)
```

**讲师口播：**
- **L 形陷阱（本课最容易漏的 bug）**：横扫发现 L 的横臂、纵扫发现 L 的竖臂——**中间那颗被找到两次**，不处理会消除两次、计分翻倍
- `_add_unique` = "收过就跳过"（`arr.has(gem)` 检查）——保证每颗宝石在结果里**只出现一次**
- **回顾 L1**：L1 第 36 页那个"临时件"里就有 `_add_unique`——当时你照抄了它，今天你看懂它为什么存在
- ⚠️ **注意：L1 已经写过 `_add_unique` 了，不要再添加一遍**——重复定义函数会编译报错！这页只讲它为什么存在

**备注框：** ⚠️ 还记得 L1 第 36 页说"第 2 课会精讲这个算法 30 分钟，并升级成正式分组版"吗？——**就是现在**。L1 的临时版少了"分组"概念，J2~J5 补上了。

## J5 · board.gd 封装①：find_matches（摊平匹配组）

**标题：** find_matches：把"一组一组"摊平成"一颗一颗"

**代码块（⚠️ 替换操作：先把 L1 的旧 `find_matches`（内联扫描版）整段删掉，再粘贴这个新版）→ 📌 归属：board.gd：**

```gdscript
func find_matches() -> Array:
	var matched: Array = []
	var groups := find_match_groups()
	for group in groups:
		for gem in group:
			_add_unique(matched, gem as Gem)
	return matched
```

**讲师口播：**
- `find_match_groups` 返回的是**"一组一组"**（每个组是一个数组）——但消除/计分需要的是**"一颗一颗"**的名单
- `find_matches` = 摊平：遍历每个组，把宝石一颗颗收进一个大数组
- **为什么收的时候要过 `_add_unique`？**——同一颗宝石可能同时在横组和竖组里，直接收会重复（J4 的 L 形陷阱）
- ⚠️ **这是替换不是追加**：你 L1 已经有一个 `find_matches`（内联扫描版），先整段删掉旧的，再粘贴这个新版——不然函数重复定义，编译直接报错
- **💡 简化思想（呼应 L1 黑盒法）**：删掉旧版、粘上新版，`find_matches()` 的**接口没变**（函数名 + 返回 `Array`）——L1 里调用它的 `ensure_no_initial_matches` **一行都不用改**，自动用上新版。这就是「接口稳定，实现可换」：调用方只认接口，内部随便重构都不怕。改完 F5 棋盘能正常生成 = 替换成功

**备注框：** 这 7 行把 J2 的 45 行"包装"成了一个好用的接口——**封装**：把复杂的东西包起来，外面只看到简单的入口。再加上刚才的「接口不变、实现可换」——**接口想清楚，后面怎么改都不怕**。程序员的日常。

## J6 · board.gd 内部件：_swap_grid_data + _animate_swap_pair（数据与表现分离）

**标题：** try_swap 的两个小帮手：数据与表现分离

**代码块（复制粘贴处，13 行）→ 📌 归属：board.gd（L1 已有，追加）：**

```gdscript
func _swap_grid_data(a: Gem, b: Gem) -> void:
	var pos_a := a.grid_pos
	var pos_b := b.grid_pos
	grid[pos_a.x][pos_a.y] = b
	grid[pos_b.x][pos_b.y] = a
	a.grid_pos = pos_b
	b.grid_pos = pos_a

func _animate_swap_pair(a: Gem, b: Gem) -> void:
	var tween := create_tween()
	tween.set_parallel(true)
	tween.tween_property(a, "position", grid_to_world(a.grid_pos), 0.15)
	tween.tween_property(b, "position", grid_to_world(b.grid_pos), 0.15)
	await tween.finished
```

**讲师口播：**
- **数据与表现分离（本课第三个新思维）**：`_swap_grid_data` 先换"真相"（grid 数组 + 每颗宝石记录的 grid_pos），`_animate_swap_pair` 后播"画面"（屏幕移动）——弹回时也是先换数据再播动画（J7 第 8、10 行重复调用它们）
- grid 是棋盘的"真相"——宝石的 `grid_pos` 必须跟着数据走（**两边一致原则**）
- `_animate_swap_pair`：📍 **第 3 课 T3 模板（动画串行）**——今天只贴代码 + 一句话"两颗宝石并行滑过去，等播完再继续"，不精讲

## J7 · board.gd 组装①：try_swap（回滚套路，黑盒揭开！）⭐

**标题：** try_swap：黑盒打开——先换 → 检查 → 不行就弹回

**开场口播（开盒）：**
「还记得交互层 `_do_swap` 里那句 `await board.try_swap(a, b)` 吗？当时我们说『黑盒，内部判定层拆』——**就是现在。** 拆开它，你会看到里面全是刚学的零件。」

**伪代码先行：**

```
【伪代码】尝试交换两颗宝石：
  ① 空 / 不相邻 → 直接拒绝（false）
  ② 交换数据 + 播放动画（J6 的内部件）
  ③ 用判定链检查（J2~J5）：有没有匹配？
     有 → 交换成立（true）
     没有 → 数据换回去 + 动画弹回（false）
```

**代码块（复制粘贴处，11 行）→ 📌 归属：board.gd（L1 已有，追加）：**

```gdscript
func try_swap(a: Gem, b: Gem) -> bool:
	if a == null or b == null:
		return false
	if not is_adjacent(a, b):
		return false
	_swap_grid_data(a, b)
	await _animate_swap_pair(a, b)
	var matches := find_matches()
	if matches.is_empty():
		_swap_grid_data(a, b)
		await _animate_swap_pair(a, b)
		return false
	return true
```

**讲师口播：**
- **黑盒打开后只有三件事**：① 前置检查（空/不相邻直接拒）→ ② 先换（数据+动画）→ ③ 用判定链检查（J2~J5 刚学的匹配链，J5 是摊平）
