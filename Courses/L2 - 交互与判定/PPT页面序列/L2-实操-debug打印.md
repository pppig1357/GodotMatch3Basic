# L2 · 实操 PPT 页面序列 —— 让代码"开口说话"（debug print）

> **用途**：L2 实操环节——「给 `_on_pointer_down` 加一行 print」的 PPT 页面序列设计
> **性质**：轻量单元（一行代码 + 一个细节猛攻），6 页封顶；**零风险**（加 print 不影响游戏）
> **配套**：代码块文档 `L2-交互与判定.md` 块1 + 逐行讲稿 `L2-逐行讲稿.md` 实操段
> **教学定位**：伪代码先行 → **猛攻 world_to_grid 的坐标数学**（输入处理环节没讲透的细节在这补）→ 动手 + 验证
> **节奏**：20min（讲师演示 5 + 细节猛攻 5 + 学员动手 8 + 验证 2）

## 页面 2/6 · 伪代码先行 —— 先写"人话流程"，再碰代码

**标题：** 我们要做的是什么事？（先想清楚再动手）

**页面内容（伪代码 —— 改造点选函数开头）：**

```
现在（改之前）：
  点击 → 拿鼠标坐标 → 翻译成格子 → 取宝石 → 判断分支

改之后（加打印）：
  点击 → 拿鼠标坐标
       → 翻译成格子坐标          ← 存进一个"中间变量"
       → 打印这个格子坐标        ← 新加的一行（就干这一件事）
       → 取宝石 → 判断分支
```

**人话：** 原来「翻译成格子」的结果是**直接**拿去取宝石的，没存下来。我们把它**先存进一个变量**，顺手打印出来——代码结构几乎不变，只是多了一行 print + 一个中间变量。

**关键提示：** 今天的改动**不改任何规则**——选中的还是选中、交换的还是交换。**只加"看"的能力。**

**代码地图标签：** 📍 `main.gd` → ⑥ 点选交互 · 开头 3 行

**讲师口播：**
「先想清楚再动手。现在 `_on_pointer_down` 的开头是：拿坐标 → 翻译 → 取宝石，一气呵成。我们要做的：**把『翻译』的结果存进一个变量，打印出来**。注意——我们不改任何规则，只是让程序把中间结果说出来。先记住这个流程，下一页我们先把一个细节讲透，再动手。」

## 页面 3/6 · 细节猛攻 ⭐ —— world_to_grid 到底怎么算的

**标题：** 猛攻细节：坐标翻译的数学（就这三步）

**页面内容（world_to_grid 代码 + 具体数字例子）：**

```gdscript
func world_to_grid(world: Vector2) -> Vector2i:
	var local := world - origin              # ① 减掉棋盘左上角
	var col := int(floor(local.x / CELL_SIZE))  # ② 除以格宽，向下取整
	var row := int(floor(local.y / CELL_SIZE))
	if col < 0 or col >= GRID_SIZE or row < 0 or row >= GRID_SIZE:
		return Vector2i(-1, -1)              # ③ 越界 → 暗号 (-1,-1)
	return Vector2i(col, row)
```

**配图（一行格子 + 数字演示）：**

```
格宽 = 64 像素。鼠标在棋盘内横坐标 local.x = 210 像素

  210 ÷ 64 = 3.28...
  floor(3.28) = 3     ← 向下取整：落在第 3 格（哪怕你点在 3.99 的位置）
  
  第 0 格(0~63)  第 1 格(64~127)  第 2 格(128~191)  第 3 格(192~255)
  [██████████]  [██████████]    [██████████]    [██████████] ← 210 落在这
```

**三个细节（一个个抠）：**
1. **为什么先减 origin？** 棋盘在窗口**居中**，不是从 (0,0) 开始——`origin` 是棋盘左上角的屏幕位置（L1 讲过 `_compute_origin` 算它）。先减掉它，坐标就变成"相对棋盘"的了
2. **为什么 floor 不是 int 直接转？** `int(3.99)` 会**截断**成 3（碰巧对），但 `int(-0.5)` 会截断成 0——**负数会出错**！`floor(-0.5)` = -1 才是对的。floor = **向下取整**，永远往小的方向走
3. **(-1,-1) 是什么？** 越界暗号——点棋盘左边/上边会算出负数，右边/下边会 ≥8，统统返回 (-1,-1)，后面 `get_gem_at` 拿到它返回 null → 触发"点空白取消"

**板书：** 数轴：0~63 是第 0 格，64~127 是第 1 格……每 64 一个格子

**代码地图标签：** 📍 `board.gd` → ④ 坐标换算 · world_to_grid

**讲师口播：**
「动手前，把翻译官的数学讲透——就三步。**第一**，先减 origin：棋盘在屏幕中间，你得先知道棋盘左上角在哪。**第二**，除以 64：一格 64 像素，除一下就知道落在第几格。**第三**，为什么用 floor 而不是直接 int？因为负数！`int(-0.5)` 会变成 0——明明点在棋盘左边外面，却算成第 0 格，bug 就来了。`floor(-0.5)` 老老实实给 -1，越界检查才能拦住它。**floor 是向下取整，int 是砍掉小数——方向不一样。**」

## 页面 4/6 · 动手 —— 改 3 行，加 1 行

**标题：** 动手：把翻译结果存下来 + 打印

**页面内容（改前 → 改后对比）：**

```gdscript
# —— 改之前（原来是两行）——
func _on_pointer_down() -> void:
	var world := get_global_mouse_position()
	var clicked: Gem = board.get_gem_at(board.world_to_grid(world))  # 翻译完直接取宝石

# —— 改之后（拆成三行 + 一行 print）——
func _on_pointer_down() -> void:
	var world := get_global_mouse_position()
	var grid_pos := board.world_to_grid(world)       # ① 翻译结果存进变量
	print("点击了格子：", grid_pos)                  # ② 打印它 ← 新加的一行
	var clicked: Gem = board.get_gem_at(grid_pos)    # ③ 再用变量取宝石（结果一样）
```

**操作步骤（讲师演示一遍 → 学员跟做）：**
1. 打开 `scripts/main.gd`，找到 `_on_pointer_down` 函数（代码地图：⑥ 点选交互，搜 `func _on_pointer_down` 直达）
2. 把原来的组合拳一行，拆成上面三行
3. 按 F5

**注意：** 改动后**游戏行为完全一样**——只是多打印一行字。改错了？删掉重来，不会弄坏游戏（这就是零风险实操）。

**代码地图标签：** 📍 `main.gd` → ⑥ 点选交互

**讲师口播：**
「现在动手。打开 main.gd，找到 `_on_pointer_down`——不会找？用搜索：`func _on_pointer_down`，回车直达（这就是代码地图导航的用处）。把原来一行组合拳拆成三行：翻译存变量、打印、用变量取宝石。改完按 F5。注意：**游戏玩法一点没变**——变的只是它开始"说话"了。」

## 页面 5/6 · 验证 —— 看输出面板

**标题：** 验证：代码在跟你说话

**页面内容（验证清单）：**

| 你做的操作 | 输出面板应该打印 |
|-----------|-----------------|
| 点第 3 列第 4 行的宝石 | `点击了格子：(3, 4)` |
| 点左上角宝石 | `点击了格子：(0, 0)` |
| 点棋盘外面 | `点击了格子：(-1, -1)` ← 越界暗号！ |
| 点不同位置乱点几下 | 坐标跟着鼠标走 |

**输出面板在哪：** Godot 编辑器**底部**的「输出」面板（或按 `F8`）——print 的内容全在这里

**常见坑：**
- 没看到输出？检查是否按了 F5 运行（编辑器里直接看代码不算运行）
- 打印的坐标"差一格"？回想 floor——点在第 3 格的右边缘，可能已经算成第 4 格了，正常

**代码地图标签：** 📍 `main.gd` → ⑥ 点选交互

**讲师口播：**
「按 F5，点宝石，看底部输出面板——`点击了格子：(3, 4)`！点棋盘外面，`(-1, -1)`！**你们现在能看见代码的内部了。** 这就是调试的起点：以后任何功能出问题，第一件事就是加 print 看数据对不对。『差一格』的同学——回想 floor，点在第 3 格右边缘就是会算成第 4 格，这是正常的。」

## 页面 6/6 · 小结 + 课后作业

**标题：** 今天你解锁了"调试"技能 + 作业

**页面内容：**
1. **小结（今天三件事）**：
   - 输入：`_unhandled_input` + InputMap 动作（"click" 不是按键）
   - 坐标翻译：`world_to_grid` 除以 64 + floor + (-1,-1) 暗号
   - 调试：`print` 让你看见代码内部——**L3 写函数，全靠它看结果**
2. **课后作业（二选一，都是改一行）**：
   - ① 把 print 改成打印**宝石颜色编号**：`print("颜色：", clicked.type)`（提示：0=红 1=蓝…5=橙，对应 L1 的 enum）
   - ② 把 print 改成同时打印**当前状态**：`print("状态：", state)`（提示：0=IDLE 1=SELECTED——点宝石前后各打一次，观察状态怎么变）
3. **挑战 More**：打印的同时，把 `board.is_adjacent(selected, clicked)` 的结果也打出来——观察"点相邻/点非相邻"时它分别是 true 还是 false

**代码地图标签：** 📍 `main.gd` → ⑥ 点选交互

**讲师口播：**
「今天解锁了三个东西：**动作输入、坐标翻译、调试 print**。作业挑一个做：打印颜色编号，或者打印状态——做完你会看到 `state` 从 0 变 1，那就是状态机在跑。**记住：print 是程序员的第三只手，L3 你们写第一个函数，就靠它验收。**」
