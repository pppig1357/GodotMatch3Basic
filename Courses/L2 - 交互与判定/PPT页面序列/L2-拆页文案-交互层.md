## B1 · board.gd 零件①：world_to_grid ⭐

**标题：** world_to_grid：屏幕坐标 → 格子坐标（L1 的反向操作）

**代码块（复制粘贴处，7 行）→ 📌 归属：board.gd（L1 已有，追加）：**

```gdscript
func world_to_grid(world: Vector2) -> Vector2i:
	var local := world - origin
	var col := int(floor(local.x / CELL_SIZE))
	var row := int(floor(local.y / CELL_SIZE))
	if col < 0 or col >= GRID_SIZE or row < 0 or row >= GRID_SIZE:
		return Vector2i(-1, -1)
	return Vector2i(col, row)
```

**讲师口播（口播讲注释）：**
- 还记得 L1 的 `grid_to_world` 吗（格子→像素）？这就是它的**反向**（像素→格子）——L1 第 33 页埋过这个伏笔
- 三行核心：**减 origin（棋盘左上角）→ 除以 64（格宽）→ floor 向下取整**
- 具体数字：鼠标横坐标 320 → 320÷64 = 5 → 第 5 列；点在第 4.7 格也是第 4 格（向下取整）
- **floor ≠ int（本页最重要细节）**：`int(-0.5)` 截断成 0（错！），`floor(-0.5)` 向下取整得 -1（对）——点棋盘左边外，int 会把它算成第 0 格，floor 才算成 -1
- `(-1,-1)` 是**越界暗号**：点棋盘外返回它 → B2 的 `get_gem_at` 拿到它返回 null → 触发"点空白取消"分支

**备注框（作业预告）：** ⚠️ 这个函数的细节是**本课实操的主角**——M11 你们要亲手打印它算出的坐标，看它"开口说话"。

**验证点：** 无，继续。

## B2 · board.gd 零件②：get_gem_at

**标题：** get_gem_at：从格子到宝石（加上组合拳）

**代码块（复制粘贴处，7 行）→ 📌 归属：board.gd（L1 已有，追加）：**

```gdscript
func get_gem_at(pos: Vector2i) -> Gem:
	if grid.is_empty():
		return null
	if pos.x < 0 or pos.x >= GRID_SIZE or pos.y < 0 or pos.y >= GRID_SIZE:
		return null
	return grid[pos.x][pos.y] as Gem
```

**页面内容②（组合拳 —— 一次点击的完整旅程，无代码）：**

```
鼠标点下去
├─ 1. 拿屏幕坐标        get_global_mouse_position()   → (320, 240)
├─ 2. 翻译成网格坐标    board.world_to_grid(...)       → (col=3, row=4)
├─ 3. 取出那颗宝石      board.get_gem_at(...)          → 一颗 Gem（或 null）
└─ 4. 交给规则判断      _on_pointer_down() 的分支      → 选中/取消/交换
```

**讲师口播：**
- `get_gem_at`：拿着格子坐标去 `grid` 数组掏宝石；越界、空盘、空位 → 返回 null——**三连防御**（口播解释三行 if 分别挡什么）
- **组合拳**：`board.get_gem_at(board.world_to_grid(world))`——从里往外读：先翻译坐标，结果塞给 get_gem_at 取宝石。**一行干两步 = 函数套函数**
- 黑盒提醒：这两步都是问 Board——Main 自己不算坐标、不查棋盘，**只负责流程**（L1 黑盒法）

**备注框：** 第 2、3 步是 Board 的"对外接口"——就像手机充电口，你知道插上去能充电就行，不用懂内部电路。

**验证点：** 无，继续。

## B3 · board.gd 零件③：is_adjacent

**标题：** is_adjacent：两颗宝石挨着吗？

**代码块（复制粘贴处，4 行）→ 📌 归属：board.gd（L1 已有，追加）：**

```gdscript
func is_adjacent(a: Gem, b: Gem) -> bool:
	var dx := absi(a.grid_pos.x - b.grid_pos.x)
	var dy := absi(a.grid_pos.y - b.grid_pos.y)
	return dx + dy == 1
```

**讲师口播：**
- **曼哈顿距离** = 横差 + 纵差（只能上下左右走，不能斜穿——就像曼哈顿的街道网格）
- `== 1` = 上下左右相邻；斜对角是 1+1=2，**不算**
- `absi` = 绝对值——⚠️ Godot 4 把警告当错误，`abs()` 编不过，必须用 `absi`（L2 常见坑，**口播重点提醒**）
- **"相邻"由 Board 说了算**：Main 调 `board.is_adjacent(...)` 只问"是/不是"，不自己算——黑盒法

**备注框：** 这颗"零件"在 M8 的规则表分支里被调用——先造好，组装时自然接上。

**验证点：** 无，继续。

## M1 · main.gd 原料①：State 枚举

> **📌 动手前**：选中 Main 根节点 → 新建脚本 → 保存为 `scripts/main.gd`（L1 的 Main 没挂脚本，现在补上）

**标题：** 状态机：游戏任何时刻都处于四种状态之一

**代码块（复制粘贴处，1 行）→ 📌 归属：新建 main.gd 并挂到 Main 根节点：**

```gdscript
enum State { IDLE, SELECTED, SWAPPING, RESOLVING }
```

**讲师口播（口播讲注释）：**
- `enum` = **枚举**：一组有名字的整数常量——写完这行，IDLE=0、SELECTED=1、SWAPPING=2、RESOLVING=3
- **状态机思想（本课第一个新思维）**：游戏任何时刻**只能处于一个状态**——不是"可能空闲也可能选中"，而是"这一刻就是空闲，下一刻才变成选中"
- 四个状态分两组：**玩家可操作**（IDLE/SELECTED）+ **动画中锁输入**（SWAPPING/RESOLVING，刹车）
- 为什么需要状态机？——没有它，点一下会同时触发"选中"和"交换"，游戏就乱了。**状态 = 游戏的记忆**

**备注框（埋钩子）：** ⚠️ 记住后两个状态 SWAPPING/RESOLVING——它们是"刹车"，M9 入口处第一次用。**代码为什么只有一行？** 四个状态的含义全部靠口播讲——这就是"去注释"：讲的人在场，不用写在代码里。

**验证点：** 无，继续。

func _select(gem: Gem) -> void:

## M5 · main.gd 零件②：_do_swap ⭐

**标题：** _do_swap：只管流程，十行代码零规则

**伪代码先行（调用树）：**

```
点相邻宝石
└─ _do_swap(a, b)              ← main.gd ⑧：只管流程
   ├─ 1. state = SWAPPING      ← 锁输入（刹车）
   ├─ 2. board.try_swap(a, b)  ← 问 Board：能换吗？（黑盒，判定层拆）
   │     ├─ 先交换数据 + 播放动画（board 内部，看不见）
   │     ├─ 检查有没有匹配（board 内部，看不见）
   │     ├─ 有匹配 → 返回 true
   │     └─ 没匹配 → 自动弹回原位 → 返回 false
   ├─ 3. 成功 → state = RESOLVING → await board.resolve_board()
   │        （消除 → 下落 → 连锁，📍 第 3 课拆）
   └─ 4. 回 IDLE，等待下一次点击
```

**代码块（复制粘贴处，11 行）→ 📌 归属：main.gd（新建）：**

```gdscript
func _do_swap(a: Gem, b: Gem) -> void:
	state = State.SWAPPING
	_deselect()
	$SfxSwap.play()
	var ok: bool = await board.try_swap(a, b)
	if not ok:
		state = State.IDLE
		return
	state = State.RESOLVING
	await board.resolve_board()
	state = State.IDLE
```

**讲师口播：**
- **`_do_swap` 十行代码没有任何规则**——只做四件事：**锁状态 → 问 Board → 等结算 → 解锁**（口播对应调用树 1~4 步）
- 交换成不成功、弹不弹回，全是 `board.try_swap` 内部的事——**这页只看接口 `try_swap(a, b) -> bool` 的用法**
- **分工思想（贯穿全课）**：Main 管流程（什么时候做什么），Board 管规则（能不能、成不成）——这就是 L1 黑盒法在真实代码里的样子
- `await` 的含义：等 Board 干完活再继续（第 3 课 T3 模板详讲动画串行）

**备注框（埋钩子 🔮）：** `board.try_swap` 里面到底怎么判定"有没有匹配"？——**休息回来第一件事就是拆它**（判定层 J7）。`board.resolve_board()` 是第 3 课的主角（判定层 J8 已留占位）。

**验证点：** 无，继续。

## M6 · main.gd 总装①（规则）：_on_pointer_down 交互规则表·一页版 ⭐⭐

**标题：** 先背规则：一页表——点击 → 反应 → 下一状态

**页面内容（交互规则表 · 一页版 —— 规则 T4 + 状态切换 T1 合并，全课可背，无代码）：**

| 当前状态 | 事件 | 动作 | 下一状态 |
|---------|------|------|---------|
| IDLE（空闲） | 点宝石 | 选中（面具亮） | SELECTED |
| IDLE | 点空白 | 无视 | IDLE |
| SELECTED（已选中） | 点自己 | 取消（面具灭） | IDLE |
| SELECTED | 点相邻 | 交换两颗（核心玩法！） | SWAPPING |
| SELECTED | 点非相邻 | 换选（旧灭新亮） | SELECTED |
| SELECTED | 点空白 | 取消（面具灭） | IDLE |

## M7 · main.gd 总装①（代码上）：_on_pointer_down 拿坐标 + 点空白 + 已选中·点自己 ⭐

**代码块（复制粘贴处，13 行）→ 📌 归属：main.gd（新建）：**

```gdscript
func _on_pointer_down() -> void:
	var world := get_global_mouse_position()
	var clicked: Gem = board.get_gem_at(board.world_to_grid(world))
	if clicked == null:
		_deselect()
		state = State.IDLE
		return
	if state == State.SELECTED and selected != null:
		if clicked == selected:
			_deselect()
			state = State.IDLE
			$SfxClick.play()
			return
```

**讲师口播：**

- 下一页：点相邻、点非相邻、以及最后那句"空闲选中"去哪了？

**备注框（⚠️ 本节课最容易写反的地方）：** 对照规则表——先处理"已选中"的情况（点自己/点相邻/点非相邻），**最后才是"空闲点宝石→选中"**。别把 `_select(clicked)` 提前写在开头，不然 `clicked == selected` 永远成立，点宝石永远"选中又立刻取消"。

## M10 · main.gd 概念+实操：InputMap「动作」——给 click 配个家 ⭐

**标题：** 用"动作"不用"按键"：先配好 click（不配 F5 点了没反应！）

**⚠️ 前提（先说清楚）：** M9 的 `_unhandled_input` 里写了 `event.is_action_pressed("click")`——但 **click 不是 Godot 自带的动作**，需要我们自己配。现在不配的话，F5 后点击任何宝石都没反应（找不到动作 → `is_action_pressed` 永远返回 false）。这页就干这一件事：把 click 配出来。

**第一步：先懂概念（为什么要用"动作"）**

| 写法 | 含义 | 问题 |
|------|------|------|
| `is_action_pressed("click")` | 按下了名为 click 的**动作** | 无——动作可在 InputMap 里任意绑定按键 |
| `event is InputEventMouseButton and event.button_index == MOUSE_BUTTON_LEFT` | 按下了**鼠标左键** | 写死按键：以后想支持触摸/键盘/手柄，代码全要改 |

**第二步：配置实操（约 20 秒，跟着点）**

```
菜单：项目 → 项目设置（Project → Project Settings）
        ↓
左侧栏点「输入映射」（Input Map）
        ↓
顶部输入框打 click → 点「添加」（Add）          ← click 动作诞生
        ↓
click 那行右侧点「+」→ 选「鼠标键」→ 勾「左键」  ← 绑定鼠标左键
        ↓
完成！关掉窗口 → F5 点宝石试试
```

**讲师口播：**
- click 是**动作名**（门牌号"302"），鼠标左键是**具体按键**（左边数第 7 扇门）——代码只认门牌号，不认门
- **为什么不用 `MOUSE_BUTTON_LEFT` 直接写死？**——今天只支持鼠标；明天想加触摸/键盘/手柄，用动作 = 只改配置，代码一行不动
- ⚠️ **强调**：click **不是默认就有的**——「动作」= 你先给一组输入起个名，再告诉 Godot 哪个键对应它。刚才是我们自己建的！
- 配好的动作会自动写进 project.godot 的 `[input]` 段（能看到，但别手改，用界面最稳）

**备注框：** 这个"动作"概念只出现一次，但它是 Godot 输入系统的地基——以后做任何游戏都这么写。改键位、加手柄、移植触摸屏，全从这页开始。

**验证点：** ① Project Settings → Input Map 里能看到 `click`（已绑定鼠标左键）② F5 点宝石 → 面具亮起（不亮 = 没配好，回看第二步）
