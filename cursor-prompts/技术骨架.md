## 4. 状态机

```
IDLE ──点选宝石──▶ SELECTED
SELECTED ──点相邻宝石──▶ SWAPPING ──动画完成──▶ RESOLVING
SELECTED ──点非相邻/空白──▶ IDLE（取消选中）
RESOLVING ──消除+下落+填充+连锁完成──▶ IDLE
步数耗尽 ──▶ GAME_OVER
```

```gdscript
enum State { IDLE, SELECTED, SWAPPING, RESOLVING, GAME_OVER }
var state: int = State.IDLE
var selected: Gem = null
```

**铁律：SWAPPING / RESOLVING 期间禁止任何输入。** 教学点：为什么游戏需要状态锁。

## 5. 核心算法

### 5.1 匹配检测 `find_matches() -> Array`
- 逐行扫描：同行连续 ≥3 个同色宝石 → 标记整段
- 逐列扫描：同列连续 ≥3 个同色宝石 → 标记整段
- 结果去重，返回匹配宝石集合（或匹配组数组）
- 教学点：二维数组遍历、边界判断

### 5.2 交换 `try_swap(a: Gem, b: Gem) -> bool`
- 仅限上下左右相邻（`abs(a.grid_pos - b.grid_pos)` 判定）
- 交换两格数据 → 调用 `find_matches()`
- 有匹配 → 进入消除流程，**此成功交换才扣步数**；无匹配 → 动画交换回去（不算步数，不扣步）
- 教学点：合法性校验、失败回滚

### 5.3 消除与计分 `clear_matches(matches)`
- 移除匹配宝石节点，grid 对应位置置 null
- 计分：每组 +N 分（如每组 3 个 = 30 分，多 1 个 +10，连锁加成 ×2 ×3…）
- 发出 `score_changed` 信号

### 5.4 下落与填充 `fall_and_refill()`
- 逐列从下往上扫描：空位上方宝石下落（Tween 动画，速度可调）
- 列顶生成新随机宝石，从网格上方落入
- 填充完成后再次 `find_matches()` → 有匹配则继续消除（**连锁**）
- 连锁直到无匹配才回到 IDLE
- 教学点：循环边界、递归/while 循环、连锁机制

### 5.5 动画串行原则（⚠️ 防止 Tween 并发错位）
**禁止到处并发 create_tween()**——多个 Tween 同时跑会导致宝石 position 与 grid 数据不同步。
推荐用 async 串行管道，每个动画完成后再进入下一步：

```gdscript
# 推荐结构（示意）
func resolve_board() -> void:
    state = State.RESOLVING
    var chain := 1
    while true:
        var matches := find_matches()
        if matches.is_empty():
            break
        await clear_matches_async(matches, chain)
        await fall_and_refill_async()
        chain += 1
    state = State.IDLE
```

教学上直接 `await tween.finished`（Godot 4 标准写法），不必引入 4.7 新 API。

### 5.6 开局无匹配 `ensure_no_initial_matches()`
- 棋盘生成后循环检测，若有初始三消则重新随机/局部替换，直到无匹配
- 避免学员还没操作就看到「自动消除」，误以为游戏出 bug

### 5.7 胜负判定
- 限步数（如 20 步）：仅「交换后产生匹配」扣 1 步
- **步数用尽即结束**：剩余步数为 0 时，当前 RESOLVING 结束后进入 GAME_OVER（不需要额外等棋盘无匹配）
- 显示结算界面（最终分数）

## 6. 信号（解耦，教学点）

| 信号 | 发出方 | 用途 |
|------|--------|------|
| `score_changed(score)` | board | UI 更新分数 |
| `moves_changed(moves)` | board/main | UI 更新步数 |
| `game_over(final_score)` | main | 弹结算界面（带最终分数） |
| `state_changed(state)` | main | 调试/教学展示 |

UI 只监听信号，不直接改游戏数据。

## 7. ⚠️ 教学友好约束（Cursor 必须遵守）

1. **注释全中文**，关键逻辑附简短解释（面向零基础学员）
2. **代码简单直白**：避免 lambda、装饰器、泛型高阶技巧；用最朴素写法
3. **函数命名清晰**：`find_matches` / `try_swap` / `fall_and_refill` 这种自解释命名
4. **不使用 autoload**（阶段一），减少概念负担
5. **不引入外部插件 / 美术 / 音效资源**，全部占位或程序化生成
6. 单文件控制在 150 行以内。board.gd 在 M3 后（匹配+交换+下落+连锁）极易超限：
   - M2 阶段 board.gd 只写生成+匹配+交换；
   - M3 拆出 `board_resolve.gd`（消除+下落+连锁）或独立 resolve 函数，并把「为什么要拆文件」作为教学点讲给学员
7. **ColorRect 显式设置 size**：ColorRect 继承 Control，挂在 Node2D 下无锚定区域，不设 size 会不可见。gem.gd 里固定 `size = Vector2(CELL_SIZE, CELL_SIZE)`
8. **遵循官方命名规范**（Godot 风格指南）：节点/类 PascalCase、变量/函数 snake_case、常量 ALL_CAPS。零基础第一天就养成好习惯
9. 每一步里程碑都要**可运行**，不交付半成品

## 8. 导出目标
- Windows Desktop (.exe) — 主交付
- Web (HTML5) — 备选：仅 Compatibility 渲染（本项目纯色方块足够）；**关闭 thread_support**（线程版需 COOP/COEP 头，GitHub Pages 等静态托管跑不了），关线程后静态托管即可在线试玩

## 9. 项目配置建议（project.godot）
- 窗口：8×64=512 + UI 边距 → 建议 **640×720**（或 720×800）
- 渲染：Compatibility（与 Web 导出一致，避免切换成本）
- 拉伸：canvas_items + expand 或固定窗口（社课选固定窗口更简单）
- 输入：建 `click` 动作绑定鼠标左键，便于课堂讲解（也可直接 get_global_mouse_position）
