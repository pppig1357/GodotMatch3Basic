## 修改清单（4 项）

### 1. 开局无解检测 ensure_has_moves（board.gd）

- **现状**：只有 `ensure_no_initial_matches`（防初始三消），没有「开局无任何可交换步」检测 —— 小概率开局死局，学员第一局点谁都被弹回，会误以为是 bug
- **新增**：
  - `has_moves() -> bool`：遍历所有相邻交换对，模拟交换后调用 `find_matches`，任一能产生匹配即返回 true（复用 `_is_adjacent` / `find_matches` / `_swap_grid_data`，注意模拟后要换回）
  - `ensure_has_moves()`：若 `has_moves()` 为 false，重排棋盘（随机换色或重新 fill_grid），直到 `has_moves()` 为 true；加安全次数上限（如 100，超出 push_warning）
  - `reset_game()` 中在 `ensure_no_initial_matches()` 之后调用
- **教学注释落点**：点明这是「匹配检测」的逆向应用 —— 检测可行步 = 枚举所有可能交换，本质与 find_matches 同族算法（为将来扩展课 hint 提示系统埋衔接伏笔）

### 2. 再点已选中宝石 → 取消选中（main.gd）

- **现状**：SELECTED 下点击已选中宝石 → 进入拖拽态，无法取消选中
- **目标**：SELECTED 下点击已选中宝石 → 取消选中，回到 IDLE（对齐 M5 已验证交互）
- **注意**：与拖拽入口共存，交互规则见第 4 项表格；取消分支里不要调用拖拽启动，`_cancel_drag()` 后 `_deselect()` 再置 `state = State.IDLE`

### 3. HUD 亮色 UI（hud.tscn，仅资源样式）

- **现状**：默认灰色按钮，与深石板灰蓝背景 `(0.12, 0.14, 0.18)` 对比不足（M5 已踩坑验证）
- **目标**：
  - 主按钮 / 标题面板：亮黄（Yellow depth 系列，**深色字**）
  - 次要与 CheckButton：亮蓝（Blue depth 系列，深色字）
  - 顶栏：Blue flat NinePatch（如适用）
- **仅改 hud.tscn 的 StyleBox 资源与控件样式，不动 hud.gd 逻辑**
- **参考**：M5 完整版 `D:\Godot Projects\godot-match3\scenes\hud.tscn` 已实装同款配色，可对照取 StyleBox 参数

### 4. 拖拽交换正式化（main.gd）

- **现状**：拖拽交换已实装（`DRAG_SWAP_THRESHOLD = 28.0`，视觉跟随限一格），但课件大纲将其列为「进阶扩展」而非正式教学内容
- **目标**：拖拽作为**正式交互模式**纳入基础版，交互规则与「再点取消」统一（对齐 M5 方案）：

| 操作 | 结果 |
|------|------|
| IDLE 点击宝石 | 选中 + 进入可拖拽态 |
| SELECTED 点击已选中 | **取消选中（回 IDLE）**【本次新增】 |
| SELECTED 点击相邻宝石 | 交换 |
| SELECTED 点击非相邻宝石 | 换选 + 进入可拖拽态 |
| 选中后按下并移动 | 拖拽交换（28px 阈值），视觉跟随限一格 |
| 选中后按下原地松开 | 保持选中 |

- **实现要点**：每次新选中后即进入可拖拽态（现有 `_start_drag_on_selected` 流程保留）；motion 事件在 `_dragging` 为 true 时触发拖拽；「再点取消」分支直接返回，不进入拖拽态
- **教学注释落点**：拖拽 = 「按下 + 位移」的连续输入模式，与「点选 + 交换」的离散输入模式并存 —— 交互层教学点

- ✅ HUD 深色背景下按钮文字清晰可读（亮色 + 深色字）
- ✅ M1~M4 教学主线不受影响：文件拆分不变、状态机语义不变、限步可选不变、导出 exe 正常
- ✅ 未引入任何 M5 扩展功能（无特殊宝石 / 模式切换 / 存档 / 提示系统）
